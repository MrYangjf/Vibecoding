# ADR-030：V3 运动控制架构 — RSI-CAMBOX 硬件级实时焊缝跟踪

> **当前状态：✅ 有效（现行运动控制架构依据）**
> **命名澄清**：本 ADR 决策时将该架构命名为「V3」，仅为当时的代际叫法。**项目自 2026-09-01 起不再按 V1/V2/V3 代际描述架构**——本 ADR 描述的 CAMBOX 硬件级实时跟踪**就是当前架构本身**，不是历史版本。原 `V3-Architecture` / `V3-MotionControlArchitecture` 归档页已删除，其仍有效的技术规范已并入 [[architecture/DeviceControlArchitecture]] 第 10 章。
> **核心变革**：运动实时链路 100% 硬件总线化，PC 退化为非实时轨迹规划器

## 背景

早期架构中，线激光焊缝跟踪采用 **PC 软件驱动的离散调整模式**：

```
线激光采图 → PC 图像算法 → 计算偏差 → MoveAbsolute 调整 Y 轴
```

该模式存在以下根本问题：

1. **抖动大（15~50ms）**：PC Windows 非实时操作系统，线程调度抖动不可控
2. **滞后严重**：软件指令从 PC 下发到控制器执行，存在通信+指令解析延迟
3. **焊缝失真**：为抑制抖动必须加滤波，导致焊缝原始轮廓被平滑失真
4. **PC 依赖性强**：Windows 卡顿直接导致丢帧、跟踪中断
5. **精度上限低**：软件周期最小 10~20ms，无法满足高速高精度焊接需求

用户提出全新控制方案：**KUKA RSI FastIPO EtherCAT + 正运动 ATYPE=25 通讯编码器轴 + CAMBOX 电子凸轮 + 线激光前置跟踪**，从根本上解决上述问题。

## 决策

### 决策1：运动实时链路完全硬件总线化

**选择**：运动控制的实时链路（主轴位置同步 → 凸轮插值输出 → Y 轴纠偏）100% 由硬件总线完成，PC 完全不参与实时运动控制。

**数据流（全链路无遗漏）**：

```
KUKA 机器人运动内核（RSI FastIPO 4ms 硬实时）
    ↓ EtherCAT PDO 周期推送（硬件级 4ms）
正运动 ZMC 控制器 EtherCAT 主站
    ↓ 映射至【ATYPE=25 通讯编码器轴】（硬件自动刷新位置）
CAMBOX 电子凸轮主轴 = 通讯编码器轴
    ↓ 硬件周期查表插值
Y 伺服从轴实时纠偏运动
```

**理由**：
- **零抖动**：EtherCAT PDO 硬件级周期推送，抖动 < 100μs
- **零滞后**：主轴数据源自机器人 IPO 插补器，超前物理位置，天然补偿机械滞后
- **焊缝 100% 保真**：只加点、不平滑、不失真，原始轮廓直接写入凸轮表
- **PC 剥离**：Windows 卡顿不影响实时运动链路，系统稳定性大幅提升
- **工业级**：符合 KUKA RSI 官方标准 + 正运动 ATYPE=25 官方用法

**替代方案**：
- Profinet + PC 虚拟轴 → 否决，仍有 4~10ms 抖动且 PC 参与实时链路
- TCP/EKRI 轮询 → 否决，15~50ms 抖动，精度最差
- 保留 V2 软件模式作为 fallback → 否决，用户明确要求完全舍弃旧架构

### 决策2：ATYPE=25 通讯编码器轴作为 CAMBOX 主轴

**选择**：正运动控制器使用 ATYPE=25（EtherCAT 通讯编码器轴）接收 KUKA RSI 推送的 ToolRelX 位置，直接作为 CAMBOX 电子凸轮的主轴。

**工作原理**：
- 该轴不跑电机、不输出脉冲
- 完全由 EtherCAT 总线硬件周期刷新 MPOS
- 等同于"机器人给了你一根虚拟光栅尺主轴"
- 可直接作为 CAMBOX 主轴使用

**轴号分配（V3 规划）**：

| 轴号 | 类型 | 名称 | 角色 |
|------|------|------|------|
| AXIS 8 | ATYPE=25 | 通讯编码器主轴 | KUKA 机器人进给主轴（CAMBOX 主轴） |
| AXIS 0 | ATYPE=0 | Y 纠偏伺服从轴 | 焊缝横向纠偏（CAMBOX 从轴） |
| AXIS 1 | ATYPE=0 | 振镜轴 | 焊缝宽度摆幅+中心（V3 第二阶段） |
| AXIS 2 | ATYPE=0 | 送丝伸缩臂轴 | 外部压力信号（V3 第二阶段） |
| AXIS 3 | ATYPE=0 | Z 轴自动对焦轴 | 送丝臂位置传感器（V3 第二阶段） |

**理由**：
- **官方标准用法**：正运动 ATYPE=25 是官方指定的 EtherCAT 编码器跟随模式
- **硬件自动同步**：位置刷新由 EtherCAT 硬件完成，无需软件干预
- **零 CPU 开销**：不占用控制器 CPU 资源，全部在总线硬件层完成
- **直接做凸轮主轴**：完全等效物理光栅主轴，可直接接入 CAMBOX

### 决策3：线激光前置跟踪 + 时间戳插值对齐

**选择**：线激光传感器前置 50mm 安装，PC 端通过双时间戳插值算法将激光测量值与机器人位置精确对齐，然后通过 `ZAux_CamBox_AddPoint` 写入原始焊缝轨迹。

**PC 端唯一工作逻辑（极简、非实时）**：

1. 接收机器人 EtherCAT 时间戳 + 主轴位置 S，建立时序缓存
2. 接收激光帧（Y_offset、T_laser 硬件时间戳）
3. 时间戳插值算出【激光真实采集时刻的机器人位置 S_meas】
4. 前置补偿：`Cam_Key = S_meas + 实测前置距离`
5. `ZAux_CamBox_AddPoint(0, Cam_Key, Y_offset)`

**时序对齐核心**：
- 激光采集时刻、机器人 PDO 时刻、网络接收时刻全部不对齐
- 通过双时间戳插值还原真实采样位置，彻底消除传输延迟误差
- 杜绝：PC 收到数据瞬间读轴位置的老旧错误做法

**理由**：
- **精度最高**：时间戳插值消除传输延迟误差，空间精度仅取决于激光传感器本身
- **PC 非实时**：PC 只做数据处理和轨迹写入，不参与实时运动控制
- **焊缝保真**：原始焊缝数据直接写入凸轮表，不做任何平滑滤波
- **前置补偿**：50mm 前置距离通过 Cam_Key 偏移精确补偿

### 决策4：完整异常保护体系

**选择**：建立工业级全套异常保护逻辑：

| 异常类型 | 保护动作 |
|----------|---------|
| EtherCAT 断连 | CAMBOX 立即停止，Y 轴锁止，报警停机 |
| 机器人停止运动 | 主轴停止刷新，Y 轴保持当前位置，不晃动 |
| 激光丢帧/无轮廓 | 停止加点，延续原有轨迹，不突变 |
| 超偏 | 超最大纠偏范围丢弃当前点，保护设备 |
| 时序异常 | 插值失败自动丢帧，不影响整体跟踪 |

**理由**：
- **工业级可靠性**：任何单一故障都不应导致设备损坏或焊接质量事故
- **故障安全**：异常时优先保持当前状态，避免突变造成更严重后果
- **分级处理**：不同异常类型对应不同保护级别，兼顾安全与生产连续性

### 决策5：架构命名为 V3，完全替代 V2

**选择**：本次架构升级命名为 **V3 运动控制架构**，完全替代 V2 的软件离散调整方案。不保留旧模式，不设 fallback。

**代际演进**：

| 代际 | 核心特征 | 调整驱动 | 实时性 |
|------|---------|---------|--------|
| V1 | TCP 轮询 + MoveAbsolute | PC 软件 | 15~50ms 抖动 |
| V2 | 工作流状态机 + 运控模块 + 回调取图 | PC 工作流 | 10~20ms 周期 |
| **V3** | **RSI + ATYPE=25 + CAMBOX 硬件级实时跟踪** | **EtherCAT 硬件** | **亚 ms 级，零抖动** |

**理由**：
- **彻底解决**：V1/V2 的核心问题（抖动、滞后、失真）在 V3 中从根本上消除
- **方向明确**：不保留旧模式，避免维护成本翻倍和架构混乱
- **用户决策**：用户明确要求"旧架构完全舍弃不要保留"

## 后果

### 正面

1. **精度飞跃**：从 ms 级抖动提升到亚 ms 级硬件同步，焊缝跟踪精度数量级提升
2. **稳定性极强**：实时链路完全脱离 PC，Windows 卡顿不影响焊接质量
3. **焊缝 100% 保真**：原始轮廓直接写入，无滤波失真，焊接质量最高
4. **架构简洁**：PC 端逻辑极简（仅时间戳插值 + 写凸轮表），维护成本低
5. **工业级标准**：KUKA RSI + EtherCAT + CAMBOX 是国际顶级焊接跟踪标准方案

### 负面

1. **硬件依赖强**：需要 KUKA RSI 授权 + EtherCAT 从站模块 + 正运动 EtherCAT 主站控制器
2. **KUKA 端配置**：机器人侧需要配置 RSI FastIPO + EtherCAT 从站 PDO 映射
3. **调试复杂度**：时间戳插值、前置距离标定需要现场精确校准
4. **旧代码废弃**：V2 运控调整工作流、MoveControlData 缓存机制等需废弃重写

### 风险

1. **ATYPE=25 配置**：EtherCAT PDO 映射与 ATYPE=25 的对应关系需参考正运动官方文档精确配置
2. **时间同步精度**：RSI 时间戳与激光时间戳的时钟源可能不同，需处理时钟偏移
3. **凸轮表容量**：CAMBOX 表长有限，长焊缝可能需要循环或分段处理
4. **现场联调**：完整功能需要机器人 + 正运动 + 激光三方联调，周期较长

## 验证标准

- [ ] KUKA RSI FastIPO 4ms 周期稳定输出 ToolRelX + 时间戳
- [ ] 正运动 ATYPE=25 轴位置随机器人运动实时同步（延迟 < 1ms）
- [ ] CAMBOX 主轴为通讯编码器轴，从轴 Y 跟随凸轮表运动
- [ ] 线激光前置跟踪：激光测量值经时间戳插值 + 前置补偿后写入 CAMBOX
- [ ] 异常保护：EtherCAT 断连、激光丢帧、超偏等均有正确保护动作
- [ ] 焊缝跟踪精度：静态偏差 < 0.05mm，动态跟踪误差 < 0.1mm（目标值，待现场验证）

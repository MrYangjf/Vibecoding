# ADR-025 代码精简规范沉淀（精准执行、免重复输入）

## 背景

用户多次提出「代码精简」类需求（变量提升、枚举/事件去重、逻辑去冗余、辅助函数归集、注释精简、设备/通讯日志规范）。每次都需用户重复输入一整套要求，效率低且口径易漂移。

## 决策

将代码精简要求**固化为 LLMWiki 标准页** `wiki/standards/CodeSimplification.md`，作为唯一标准源，并由 `wiki/index/index.md` 路由到「代码精简规范」分类。

触发精简需求时，AI 直接读取该标准页执行，**无需用户重复输入**精简要求。

标准覆盖：
1. 代码精简四维度（变量→私有成员 / 枚举事件去重 / 逻辑去冗余去互锁 / 辅助函数归集）
2. 注释精简三规则（去过程性说明 / `///` 含参数注释 / `//` 仅复杂逻辑）
3. 设备日志规范（去符号用文字 / 功能块始末记录 / 通讯全记录）
4. 适用范围：除 `*.Designer.cs`（设计器自动生成）外的全部业务源码（含 `UIDesign/` 下非设计器 `.cs`），不触及外部厂商 SDK 原生部分；以文件夹为整理单位

> **升级（2026-08-26）**：标准已升级为详尽版。原四维度细化为**五维度**（新增①文件书写整理：成员顺序/#region/XML 注释；②变量与临时变量并入无意义 null 检查；③枚举去重并入禁过度枚举；④逻辑去冗余并入 9 类禁止项；⑤辅助函数归集并入功能重叠合并/嵌套内联/死函数），并新增**检查脚本 `scripts/csharp_review.py`**（单文件静态扫描，A/B/C 三类、error/warn/info 三级）。深度反例与脚本工作流平铺于 `wiki/standards/`，文件名以 `CodeSimplification-` 前缀成组。触发约定不变：用户说"代码精简/注释精简/日志规范"即读取本页执行。

## 备选方案

1. 每次在对话里复述要求 —— 已证明低效且口径漂移，否决。
2. 仅写入 CSharpStyle.md —— CSharpStyle 偏语法，且用户要求「由 index 路由到精简代码区域」，需独立页面，否决。

## 后果

### 正面
- 精简口径统一、可沉淀、可检索。
- 用户无需重复输入需求。
- 与既有 ADR（026 枚举去重、002 C#7.3、001/034 Dispose）形成规范合集。

### 负面
- 标准需随实践迭代维护（由 AI 在 Ingest 时更新）。

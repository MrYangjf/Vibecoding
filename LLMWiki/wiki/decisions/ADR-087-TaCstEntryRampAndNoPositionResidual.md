# ADR-087 TA 力矩进入协议：冷启动停稳+方向种子+输出后下发目标

> **决策一句话**：TA 力矩进入协议：冷启动停稳+方向种子+输出后下发目标

## 背景

业主 2026-11-06 现场两组现象：①Break/Pose/Zero → TA_Auto 切换过快，TORQUE_SLOPE 无效，而 Auto↔Retract 生效；②Retract → Zero → Auto 每次先反跑再回正。代码事实：SetTorque 旧实现先 CST_Start_Move 后 CST_Output_Enable，输出关闭期间目标已写入，开输出即到目标值（冷启动不经历斜坡）；同时存在「输出态 ∧ 模式字 ∧ 目标与 slope 均未变」的复用捷径；切 CST 前不停位置运动、不清驱动器内上一次反向扭矩指令。

## 决策

1. 冷启动固定顺序：位置运动停稳（`IsMoving` 轮询，3s 超时即拒绝）→ `Set_MoveMode(CST)` → `CST_Start_Move(±1‰ 方向种子)` → `CST_Output_Enable(1)` → `CST_Start_Move(目标, slope)`
2. 热切换（输出已开且已在 CST）：直接 CST_Start_Move(目标, slope)，从当前扭矩按斜率爬升；
   同号调力与符号翻转共用同一斜率（2026-11-06 收口，[ADR-088](ADR-088-TaSharedTorqueLimit.md)）
3. 删除复用捷径：任何进入力矩出力的路径都重新下发目标与 slope，TORQUE_SLOPE 改小立即生效
4. 方向种子与目标同号，覆盖驱动器内残留的反向扭矩指令，消除开输出瞬间的反向抢动
5. 失败流不变：任一步失败撤输出并 RestoreCspMode；单飞、5s 力矩生效超时、闸门、上色、自动 ZeroPose 选中态均不改

## 备选方案

- **软件逐级爬坡**：由本层按 slope 每 20ms 分步下发目标扭矩。能 100% 保证斜坡，但占用后台线程、扩大 `WaitTaTorqueOn` 语义，且与驱动器自带 slope 重复，弃用。
- **仅删复用捷径**：只解决「同参数跳过」，不能解决冷启动开输出即到目标值，也修不了位置残留与反向扭矩继承，不满足验收。
- **开输出前先下发 0 扭矩**：台达把 0 判为非法参数（4609），不可行；改取 ±1‰ 方向种子。

## 后果

### 正面
- 冷启动与热切换都按配置的 `TORQUE_SLOPE` 建立扭矩，Break/Pose/Zero → Auto 不再「瞬间到位」。
- 位置残留先停稳、方向种子先同号覆盖，消除「先反跑再回正」。
- 任何路径都重新下发目标与 slope，改小爬升速率立即生效，不再有隐性复用。

### 负面
- 冷启动多一次 `CST_Start_Move`（方向种子）与一次目标重发，多两条指令耗时（微秒级）。
- 停稳等待最坏增加 3s（仅在位置运动未停时触发，且超时即拒绝切换，不会带着残留运动进 CST）。
- 驱动器是否在输出关闭期间内部执行 slope 爬升未获台达手册确证；本方案用「输出开启后再下发目标」规避该不确定性，若现场仍无斜坡需回看 `CST 扭矩冷启动` 日志定位。

## 演进记录

### 2026-11-06 方向反转仍慢：Auto→Retract 4s 与 Retract→Zero→Auto 先反跑 ⛔ 本节结论已被 ADR-088 取代

> ⛔ **已废弃**：本节曾提出「符号翻转改用第二条更快的斜率」的两段式对策（后成 ADR-088），
> 已由业主 2026-11-06 收口**全部删除**——反向穿越斜率、交接点、速度守卫三参数与两段式逻辑均不存在。
> 删除**不解决**跑飞与撞击：其根因是 CST 只约束出力、不约束速度（见 [ADR-088](ADR-088-TaSharedTorqueLimit.md)）。
> 下方正文仅作历史留痕，⛔ 不得据其改码或调参。

- **算术定因**：`TORQUE_SLOPE` 单位 0.1%/s，数值即 ‰/s。`slope=200`、Auto +270‰ ↔ Retract −270‰ 时 `|Δ|=540‰`，`t = 540 / 200 = 2.7s`；再加位置停稳轮询、`WaitTaTorqueOn` 确认窗与指令开销，与现场 4s 吻合。Retract→Auto 冷启动虽经方向种子，但种子 ±1‰ 到目标仍按 slope 爬 `270/200 = 1.35s`，期间**符号为旧方向的目标指令仍在出力**，轴顺惯性继续走 —— 即「先反跑」。
- **假设判定**：位置残留假设已由上一轮 `EnsureCspMotionStoppedForTorque` 覆盖；若日志出现「CST 进入前 位置运动已停稳」仍反跑，则残速假设被证伪，只剩「扭矩穿越零点窗口内仍输出旧方向力」。驱动器收到异号目标是连续爬升还是先归零再爬，手册无记载，本层以「连续爬升」为保守假设。
- **当时的决策（不撤力，改斜率）**：曾为 `SetTorque` 增加第二条反向斜率形参、符号翻转时整段改用它下发。**该形参与对应配置键已于同日全部删除**（ADR-088）。
- **为何不采用「撤力→等停稳→冷启动种子→开输出」**：撤力会引入一段完全无出力的窗口，送丝/保压靠弹簧与丝材反力，无出力即回退，反而**放大**「先反跑」并可能造成丝打滑；且撤力重建要走完整冷启动链，耗时（停稳 3s 上限 + 切模式 + 种子）大于 2.7s，净收益为负。备选「反转期间临时抬高上限」被否：上限同时是 CSP 推动阻抗与 Break 保压的安全值，临时抬高会削弱打滑保护。
- **当时保留现状的代价**：反转仍有一次穿零，只是窗口按两条斜率比例缩短。
- ~~**配置约束**：UI 校验反向斜率 ≥ `TORQUE_SLOPE`，填小即报错。~~ 已随参数删除作废。

### 2026-11-09 撤力失败不伪造状态：可观测 + 可区分 + 可恢复

- **问题**：`StopTorque` 只判 `CST_Output_Enable(0)` 返回值，失败时仅一条通用 `LogFail`（无回读值），且 `TorqueOutputEnabled` 保持 true 但上层无从区分「正常出力中」与「撤力失败残留出力」；`ServoOff` / 急停不撤力。
- **决策**：撤力失败**不改** `TorqueOutputEnabled`（硬件真值，伪造 false 会让上层误判安全）；新增只读 `TorqueRetractFailed` / `TorqueRetractFailCode` 记录撤力结果与返回码。
- **可观测**：失败日志带轴名、返回码、描述、`GetCurrentTorque()` 回读力矩与 `GetMoveMode()` 模式字（无 CST 输出使能状态回读 API，回读值用这两项替代）。
- **可恢复**：`ServoOff` 在 `Set_Svon(0)` 前、急停 `AxisStop(Emergency)` 在 `Emg_Stop` 成功后，均按 `TorqueOutputEnabled` 补一次 `StopTorque` 重试；再次 `StopTorque`（含 `ExitTaTorque`）本就重试。
- **清零时机**：下次撤力成功、或重新下发目标成功（热切换/冷启动）时清零——此时输出态已确定，残留风险不再成立。
- **边界**：`TorqueOutputEnabled` 语义不变，未改任何现有公开签名。

### 2026-11-10 撤销同号种子；冷启动改为先参数后使能；反号走撤输出

- **决策**：①冷启动删除 ±1‰「同号种子」，首条力矩指令即目标本身；②顺序为「停稳 → 切 CST → 下发目标/斜率 → 开输出」；③CST 内反号先 `CST_Output_Enable(0)` 回到无方向保持电流，再下发反向目标并重新使能（不切 CSP，避免回退到旧位置目标）。
- **依据**：位置模式电流已回到无方向值，切 CST 后无从继承旧方向；种子会在改参数前先送出一条反向指令（现场监控可见）。
- **反号耗时推算**：撤输出瞬时 + 新方向建立 `|Δ|/slope`（270/200≈1.35s），替代跨零 `2|Δ|/slope`（2.7s）。
- **⚠️ 待业主裁定（与本节 2026-11-06 条目冲突）**：
  1. 「先参数后使能」使开输出瞬间即到目标值，冷启动不再经驱动器 slope 爬升 —— 与「末次目标必须在输出开启之后」的修复相冲突（该修复正是为消除「切换很快」的瞬时到位）。
  2. 反号撤输出会引入无出力窗口（压紧力回落保持位）—— 与「为何不采用撤力重建」的理由相冲突（当时判断无出力会放大回退）。
- **验证**：仅代码路径变更，实机未验；待观察电流曲线正→负过渡时间与是否出现零力平台/阶跃。

### 2026-11-10（第三次）反号改走「位置停止」，两条待裁定项按新事实收口

- **业主新裁定（原话）**：「先做 enable 关闭，然后切换位置模式做 Stop（停止），然后切换模式 csp 写入反向参数，然后 enable」。
- **新序列**（`DeltaMontionAxis.ReverseTorqueOutput`）：`CS_ECAT_Slave_CST_Output_Enable(0)` → `SetPosition(GetPosition())` 锁当前位 → `CS_ECAT_Slave_Motion_Set_MoveMode(CSP)` 并回读模式字 → `GetCommandPosition()` 复读、偏离即复写 → `AxisStop(Deceleration)` + `WaitReverseStopDone` → `Set_MoveMode(CST)` 并回读 → `CST_Start_Move(目标, slope)` → `CST_Output_Enable(1)`。
- **CSP 回退防护**：切模式**前**把位置目标写成当前反馈位置；切到 CSP 后再回读指令位置，偏离 >0.001 即复写一次。位置环目标即当前位，Stop 不产生反向位移。
- **口径判定**：业主原话第二处「切换模式csp」按上下文判为「切到 CST 写反向参数」。依据：末步 `CST_Output_Enable(1)` 只在 CST 有效，停在 CSP 无法建立扭矩；`CST_Start_Move` 本身也是 CST 指令。⛔ 未按字面做成「纯 CSP 停止后不下扭矩」。
- **实测依据**：业主实测「位置环把电流拉回无方向保持位」比等斜坡跨零快很多。
- **对上方两条「待业主裁定」的处置（旧结论标记为被本次实测取代，不删历史）**：
  1. 「先参数后使能 → 开输出瞬间即到目标」：旧冲突**已被本次业主要求的序列取代** —— 业主明确要求先写目标再 enable，冷启动同序保持不变；仅保留「实机电流曲线」这一观察项。
  2. 「撤输出引入无出力窗口、会放大回退」：旧结论**已被业主实测取代** —— 无出力窗口由 CSP 位置环 Stop 立即收口，比跨零斜坡快，回退风险由「锁位 + Stop」消除。
- **未动**：同号热切换（直接 `CST_Start_Move`）、冷启动首切（停稳 → 切 CST → 写目标 → 开输出）、±1‰ 种子仍保持已删除。
- **日志**：新增「撤除扭矩输出 / 位置目标锁定 / 已切回位置模式 / 位置模式停止完成 / 已切到 CST / 已写入反向目标 / 已开启扭矩输出」七条动作日志，失败分支带返回码或模式字；保留「反号走位置停止」。
- **验证**：MSBuild 0 error / 0 warning；实机待验。

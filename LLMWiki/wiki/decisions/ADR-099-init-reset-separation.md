# ADR-099 初始化与复位分离

> **决策一句话**：初始化只做连接与使能，回零与工作零位只在复位入口按轴能力执行

## 背景

调试期把 TA 回零与工作零位塞进初始化收尾（D01），初始化耗时不可控、失败原因混杂；机器人通讯在初始化节点中非强制（D03），真实模式缺机器人也能进「已初始化」；初始化部分失败后没有「保留已连、只补未连」的入口（D06）；IOWork 从启动第一拍就判安全互锁，设备未连接先报 Alarm（D16）。旧的复位链只清急停、把回零/回标定留给后续流程步，复位完成时轴并未到工作零位。

## 决策

1. 初始化只做连接 + 使能，结束态固定为「已连接 / 已使能 / 未回零 / 无运动」，收尾日志按该口径打印。
2. 回零与工作零位只在复位入口执行，初始化链不再调用回零。
3. 机器人通讯节点 `Mandatory=true`：真实模式未连机器人即初始化失败并给原因；模拟测试走 `EnsureRunningForSimulation` 的既有旁路，不受该强制项阻塞。
4. 初始化受理门禁：运行中、急停、复位中一律拒绝重复初始化；规划目标全部已连接时直接跳过（补连判据），已连设备不重复连接。
5. 初始化期间 `IsInitializing=true`，`IOWork` 不参与安全互锁门控，避免设备未连先报 Alarm。
6. 复位沿用既有链路：`ResetMachine()`（开启复位动作）→ `thIOWork` 扫到 `IoReset` → `DoResetMachine()` 复位线程 → `CascadeResetProcess()` 逐子流程 → 各子流程 `ResetProcess()` → 各管理器动作。⛔ 不新增第二套复位入口。
7. 运控子流程 `MotionControlWorkflow.ResetProcess()` 承担门槛 L1 与按轴能力分支：需回零轴经管理器 `HomeAxisAndWait` 回零后再工作零位，免回零轴经管理器定位动作只去工作零位。失败停在 L2/L3，可再次复位重试。
8. 回退开关 `INIT_RUN_TA_HOME=1`：恢复初始化末尾自动回零与工作零位，仅作阶段 3 回退路径。

## 备选方案

- 初始化仍自动回零，仅加超时 → 失败原因仍混杂，且未复位态不可观测，弃。
- 初始化失败整体回滚断开全部设备 → 会把已正常设备一起断掉，弃。
- 复位按轴名分支（`if (axis == "Y")`）→ 新增轴立即失效，违反 ADR-098，弃。
- 复位只清急停、等流程步回标定 → 复位返回时轴未到位，无法证明 L4，弃。

## 后果

### 正面

- 初始化结束态可判定，V1 有日志证据；失败后可只补连缺失设备。
- 复位结果可证明：需回零轴走到 L4，免回零轴只走工作零位，失败可重试。
- 启动不再因互锁先报 Alarm，真实原因不被掩盖。

### 负面

- 初始化完成后设备处于「未回零」，流程必须经 L4 门槛才可自动焊接（阶段 4 落地）。
- 复位是阻塞链，耗时取决于回零行程；只能由后台复位线程调用，⛔ 不得在 UI 线程或 IO 扫描线程直接调。
- 机器人通讯强制后，真实模式缺机器人时初始化失败属预期行为，现场需先接通机器人或切模拟。

### 2026-11-17 · 决策 D27 · 手动回零与复位回零共用 TryHomeAxisWithWait 同一实现，已回零结论不区分来源
- **变更**：手动回零与复位回零共用 TryHomeAxisWithWait 同一实现，已回零结论不区分来源
- **理由**：非阻塞回零不置已回零结论，导致手动回零后 TA 指令全被拒
- **影响**：回零结论唯一置位点在 WaitAxisHomed；两路回零语义统一

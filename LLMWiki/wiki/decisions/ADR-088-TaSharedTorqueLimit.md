# ADR-088 CSP/CST 共用单一扭矩上限（TA_TORQUE_LIMIT_N + 16#6072）

> **决策一句话**：位置模式推动阻抗与力矩模式最大出力共用 `ROOT/TA_HOME/TA_TORQUE_LIMIT_N`，软件在 `SetTorque` 唯一下发点钳制 CST 目标，驱动侧在伺服 OFF 窗口写 `16#6072`。

## 背景

业主 2026-11-06：「将扭矩上限 = 力矩模式输出的最大值，这样位置模式力矩值就和力矩模式一致，更丝滑；整个轴在调试推动时都是一样的阻尼感。」工程目标 = **一个上限、一个配置源、一个下发点**，不是「位置模式不设限」，也不是两套限值各调各的。

前置查证结论（[[decisions/ADR-Index]] 同轮记录）：

- `16#6072` = CiA402 **Max torque**（UINT16、额定转矩 0.1%、标准默认 1000=100%），对转矩给定做幅值钳位。**台达 GMC 手册未收录其语义/单位/默认值/写条件**；本机无 ASDA 伺服对象字典手册，因此「伺服 ON 时能否写」**无法确证**。
- 因此不能采用「运行期动态跟随力值」的形态：上限只能在**伺服 OFF 窗口写定值**。改上限后需重新使能伺服才改变位置模式阻抗。
- 台达 PLC 侧 `0x6072 + (轴号-1)*0x800` 是**直写 CoE** 的约定；我们的运控 API 用 `NodeID + SlotNo` 定位（单轴 SlotNo=0，四轴 SlotNo=0~3），由主站 API 内部寻址。**⛔ 不手工加 0x800 偏移**，否则会在四轴从站上写错轴。
- 代码现状：`AdaWeldSystem/` 内 0x6072/0x60E0/0x60E1/0x6087 **0 命中**；`DeltaSlaveDevice.SdoWrite` 无调用方；SDO 读写统一走 `EtherCATMasterNative.CS_ECAT_Slave_SDO_*`。

## 决策

1. **单一配置源**：新增 `ROOT/TA_HOME/TA_TORQUE_LIMIT_N`（N，缺省 37 = 100% 力量基准 = 不降额）。UI 入口在「系统设置 → TA 电机 → 参数」弹窗的**力矩输出**分区（与扭矩爬升速率、扭矩方向同段）。
2. **单一换算点**：`DeltaTaHomeConfig.GetTorqueLimitPerMille()`（上限 ÷ `TA_FORCE_100PCT_N` × 1000，钳 1~1000）。⛔ 不在别处再写一套换算，避免「参数弹窗一个值、代码里又一个常量」。
3. **单一软件下发点**：`DeltaMontionAxis.SetTorque` 在参数校验后按 `TorqueLimitPerMille` 钳制目标幅值；`MotionControlWorkflow.TryResolveTaTorque` 在指令入口复用同一换算做提前提示（Auto/Retract 共用）。
4. **驱动侧同值**：`ServoOn()` 在 `Set_MoveMode(CSP)` **之前**、`Set_Svon(1)` 之前调 `EnsureDriveTorqueLimit()` 写 `16#6072` 并回读校验；失败/回读不符只告警、不阻断使能（软件钳制仍生效）。**写入通道唯一** = `DeltaSlaveDevice.ReadSdo/WriteSdo`（与 `16#6098/0x6099/0x609A` 及其它对象字典读写同一套握手：前置 10ms → `SDO_Check_Done` 轮询 → `SDO_Get_ErrorCode` 取中止码 → 邮箱类返回码 30ms 退避重试 3 次）。台达 P 参数旁路 `P1-12`（`0x210C` + 轴号子索引）**已删除**。每次伺服使能重试一次；`ServoOff()` 把「已写值」置为未确认，下次使能重写，防驱动器掉电丢值后仍跳过。
5. **回读三态**：回读必须区分「API 返回码（请求未发出）」「驱动器 SDO 中止码」「轮询超时」，⛔ 读失败不得回落成 0‰ 参与比较；写失败、读失败、值不符三种日志各自独立。三态由 `DeltaSlaveDevice.Describe` 统一生成。
6. **安全底线**：上限不得低于位置保持实际需要的转矩。UI 校验拒绝「上限 < 当前 `TA_FORCE_N`」；装载期非法值（≤0 / 超基准）按 100% 基准兜底并告警，⛔ 不兜底成小上限。
7. **日志四态**：`CST 扭矩上限钳制`（目标超上限）/`已贴边`（目标 = 上限）/`余量仅 x%`（≤10%，如 270‰/300‰）/`有余量`；明确「被钳制 ≠ 已出力」。

## 备选方案

- **运行期每次进入力矩前动态写 0x6072 = 当前目标**：手感最贴合力值，但伺服 ON 可写性未确证，写失败会打断焊接流程，弃用；现场若实测可写再升级。
- **只做软件钳制，不写驱动**：CSP 推动阻抗仍由驱动器 P1-12 决定，达不到「两种模式同阻尼」，不满足业主意图。
- **上限用 % 额定而非 N**：工艺人员看不懂额定百分比与 37N 基准的两套口径，弃用。

## 后果

### 正面
- 位置模式推动阻抗与力矩模式最大出力来自同一个值，模式切换手感不跳变。
- 上限贴边/余量不足会打印危险比例，Break 保压打滑与跟随误差可提前暴露。
- 缺省 = 100% 基准，上线零行为变化，不会让现役轴推不动。

### 负面
- 改上限后需重新使能伺服才改变位置模式阻抗（CST 软件钳制即时生效），必须在交接说明中讲清。
- `16#6072` 是否为台达该机型认的对象/单位未获手册确证；若回读不符，日志会给出明确告警，届时需按 ASDA 对象字典或 ASDA-Soft / DIASelector 现场核定（⛔ 不再走 P1-12 猜测旁路）。
- 伺服 OFF 窗口多一次 SDO 写 + 一次回读（仅在值变化时发生）。

## 验证

- 编译：真实 `MSBuild /t:Rebuild /p:Configuration=Debug` EXIT=0（仅既有 warning）。
- 静态：八扫描器全绿；`TA_TORQUE_LIMIT_N` 已进 `WriteConfigNodes` 模板，`ConfigSelfHeal` 按既有「只增不改」路径补键。
- 待现场：分别用位置模式与力矩模式手推轴比对阻尼感；看日志 `扭矩上限已写入驱动器 16#6072` 与 `CST 扭矩上限关系`。

## 演进记录

### 2026-11-11 满扭矩限定在回零期间，回零确认后在线回落

- **业主口径**：「不能只在回零的时候满扭矩，回零正确结束就修改扭矩到我需要使用的大小」——1100 加一轮复核发现 `FullTorqueOnEnable` 使每次使能都写满量程，回零后位置模式推动阻抗长期停在 1000‰。
- **在线可写性结论（确定的是证据性质，未确证的是驱动器行为）**：本机 `raw/delta` 无 `16#6072` 条目；现场 `SubIndex 1 → 0x1302` 的 `0x1302` 是台达 DLL 返回码 `ERR_ECAT_SDO_RETURN`（`EtherCAT_DLL_Err.cs`），**不是 SDO 中止码**，且该探测发生在伺服 OFF 窗口，**无法据此判断使能态可否写**。
- **落地形态**：`16#6072` 仍在使能窗口写满量程（供回零推动）；`WaitAxisHomed` 确认后调 `DeltaMontionAxis.RestoreTorqueLimitAfterHome()`，在**伺服 ON 状态**写回 `TorqueLimitPerMille` 并回读校验。写通即在日志宣告回落；写不通只告警「位置模式推动阻抗仍为满量程」，**不新增 OFF/ON 循环**（须业主动拍板才可加）。
- **时点**：回零确认后、`ExecuteTaZeroPose` **之前** —— ZeroPose 是普通绝对定位，不需要推动力，先回落可避免其仍以满量程推动。
- **未改**：`SetTorque` 的 `TorqueLimitPerMille` 软件钳制与下压力换算保持原样。
- **现场取证**：日志 `16#60E0/16#60E1 只读探测`（每进程一次）给出返回码，用于判断是否可改用正负扭矩限值对象；`回零后扭矩上限已回落` / `回落失败` 两条直接反映在线写是否可行。

### 2026-11-06 现场 11:14 回读 0‰ → 写入链路补强

- **现象**：`扭矩上限写 16#6072 后回读 0‰ ≠ 下发 1000‰，按未生效处理（下次使能重试）`，上限等于没写进去。
- **定因（代码层，确定）**：旧 `TryReadSdoUInt16` 只有「读成功 / 读失败」两态，失败时 `out` 值保持初始化的 0 并继续参与 `readBack != limit` 比较 → 日志把「读失败」打印成「回读 0‰」。即**回读为 0 与回读失败被合并**，现场无法判断对象是否实现。另：`SDO_Check_Done` 在上一笔完成后保持 0，发起读后立刻轮询会命中陈旧状态并读到未填充缓冲。
- **对象层结论先撤回**：当时据「回读 0」推断「本机型未实现 16#6072」证据不足，11:34 现场日志已证伪该推断的前提（见下条）。

### 2026-11-06 现场 11:34 `0x1305` 误标为 SDO 中止码 → 标签与探测重做

- **关键纠正**：`0x1305` = 十进制 **4869**，与写 P1.087/P1.088 时出现的码相同。标准 SDO abort 段是 `0x0500~0x06FF`，`0x1305` 属**台达 DLL 自身返回码**段（本地 `EtherCAT_DLL_Err.cs` 表内只有 `0x1304 = MAILBOX / SDO_BUFFER_FULL / ESC_FAILED`，**`0x1305` 未收录**）。旧日志标成「SDO 中止码」是错的，会误导结论。
- **推论**：API 返回非 0 且属邮箱类 → **请求很可能根本没发出去**，不能据此判定驱动器不支持该对象。故「16#6072 未实现」改为**待验证**。
- **P1-12 读回 65186（0xFEA2）的定因（确定）**：旧实现走 `DeltaServo_Read_Parameter`，把 `SlotNo`（单轴 = 0）当轴号传，等价于按 `SubIndex=0` 读台达 P 参数；而 PLC 示例是 `uiSubIndex := iSubIndex_Axis`（**1 基轴号**）。子索引错位 → 读到别的对象，值无意义。
- **决策补强**：①日志把「API 返回码」与「驱动器 SDO 中止码」分列，`DescribeApiReturn` 给出 0x1304/0x1305 已知信息与「请求可能未发出」的判断；②新增 SDO 基线读 `16#6041` 状态字，基线失败时**禁止**对 16#6072 下「未实现」结论；③16#6072 只读探测 SubIndex 0 与 1，读通哪个才写哪个；④P1-12 改走 CoE `0x210C` + `SubIndex = 轴号（1 基 = _slotNo + 1）`、长度 2，读回按 0~300% 或 0~3000‰ 判读，读不到/值域不符仍拒绝写；⑤邮箱类返回码（0x1304/0x1305）退避 30ms 重试 3 次；⑥「不可用」不再永久生效——**每次 ServoOff/On 周期重试一次**，日志带轮次计数与两条通道各自的失败码。
- **仍待现场确证**：`0x6072` 是否实现、P1-12 是否即转矩限制、`0x1305` 的官方含义。交叉验证手段 = 台达 ASDA-Soft / DIASelector 直连读一次 P1-012 与 0x6072 真值。
- **写入窗口**：仍在伺服 OFF 窗口（`ServoOn` 内 `Set_Svon(1)` 之前），运行期可写性未确证，维持原约束。

### 2026-11-06 11:51 统一 SDO 通道（业主否掉「两套函数」）→ 删除 P1-12、窗口前移

- **业主口径（否决理由）**：`写扭矩这个跟写home_mode是一类的，为什么你要用不同函数？？` —— 写 `16#6072` 与写 `16#6098` 本质相同（同一通道写一个对象字典参数），理应同一 API、同一握手。
- **原路径差在哪（确定）**：
  - `16#6098/6099/609A` 走专用接口 `CS_ECAT_Slave_Home_Config(CardNo, NodeID, SlotNo, Mode, Offset, FirstVel, SecondVel, Acceleration)`，**握手由 DLL 内部完成**，项目侧不碰 `SDO_Check_Done`。该函数**不接受 Index 形参**，无法用于 `16#6072`。
  - `16#6072` 原为轴类**自拼**：`CS_ECAT_Slave_SDO_Quick_Send_Message` + 自己轮询 `CS_ECAT_Slave_SDO_Check_Done` + 自造 `SdoReadResult` / `WriteSdoWithMailboxRetry` / `ReadSdoUInt16`。同一通道两套时序，即不一致的根源。
- **统一后（确定）**：`16#6072` 的写与回读全部走 `DeltaSlaveDevice.ReadSdo/WriteSdo`（项目既有 SDO 网关，`WeldHeadSlaveDevice` 亦在用）。`DeltaSlaveDevice` 补齐三件事：①发起前 10ms 前置等待（`Done` 在上一笔完成后保持 0，立刻轮询会读到陈旧状态）；②邮箱类返回码（`0x1304`/`0x1305`）30ms 退避重试 3 次；③`SDO_Get_ErrorCode` 取驱动器中止码，`Describe` 输出三态。轴内自造机制全部删除（Grep 确认无其它调用方）。`VerifyHomeModeReadback`（`16#6098` 回读）一并改走 `_sdo.ReadSdo`。
- **SubIndex 语义（确定）**：`DeltaSlaveDevice` 的 `subIndex` 形参是**对象子索引**（`16#6099` 用 1/2 表高速/低速即证），与「P 参数子索引填轴号」是两套不同约定。故 P 参数旁路不能挂在同一形参上；这正是 `P1-12` 读回 `65186` 的成因。
- **P1-12 旁路删除**：映射未经手册证实（`0x210C` + 1 基轴号）、曾读回垃圾值，且与标准对象通道的 SubIndex 语义冲突；统一通道后已有完整三态诊断，不再保留猜测旁路。
- **写入窗口前移**：`EnsureDriveTorqueLimit()` 从 `Set_MoveMode` **之后**挪到**之前**。切模式（写 `16#6060`）本身占邮箱，紧跟着发 SDO 是 `0x1305`（邮箱未就绪 / 上一笔事务未结束）的典型触发条件；改为在邮箱空闲窗口先发，不靠加延时硬凑。日志标注实际窗口。

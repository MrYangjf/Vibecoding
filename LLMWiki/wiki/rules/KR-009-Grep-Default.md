# KR-009 Grep 是默认定位法

> **一句话规则**：code-graph 已废止；用 Grep 定位符号与追踪影响面

## 适用范围

**适用**：Step 0.7（定位符号 / 读行区间）与 Step 2.5（追踪影响面）。  
**不适用**：无（本项目无其他代码定位方式）。

## 规则正文

1. code-review-graph 已于 2026-08-19 废止，⛔ 不作为必需步骤，也不得用它替代 Grep。
2. Step 0.7 用 Grep 定位符号并读**精确行区间**；Step 2.5 用手动多层 Grep 追影响面。
3. 搜索无命中时先怀疑**写法**（大小写 / 命名空间 / 匹配模式），再断言「不存在」。

## 判据

- ⛔ 违反判定：报告出现「已用代码图谱定位」而未给出 Grep 模式与命中位置。
- ✅ 机器校验：Step 0.7 / 2.5 记录含具体 Grep 模式与命中行号。

## 反例

| 反例（违规写法） | 正解 |
|---|---|
| 「用图谱工具查一下在哪」 | Grep 符号名 → 读精确行区间 |
| Grep 一次没命中就断言「没有这个类」 | 先换写法与路径再下结论 |


### 2026-11-17 · Grep 的范围收窄：先 CodeMap 后符号
- **变更**：Grep 仍是唯一定位法但须限定范围:Step 0.7 的 Grep 须带[符号名]且 path 收窄到 CodeMap 命中的 1~3 文件/目录;⛔ 禁止 Phase 0 阶段对全项目 AdaWe
- **理由**：业主反馈反复全盘扫描使 CodeMap 代码记忆作用失效
- **影响**：报告须记录 Grep 模式+path 范围+命中行号;宽泛全库扫描须有 CodeMap 未命中的理由

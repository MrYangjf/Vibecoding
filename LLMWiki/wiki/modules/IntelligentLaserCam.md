# IntelligentLaserCam 模块 — 英莱(IntelligentLaser) 线激光相机

> 英莱(IntelligentLaser / ANLE) 工业 **3D 线激光（轮廓）相机** 模块，位于 `LineLaserCam/IntelligentLaserCam/`，命名空间 `AdaWeldSystem.LineLaserCam.IntelligentLaserCam`（与目录结构一致，归属 `LineLaserCam` 父命名空间）。
> 与 `SmartRayCam` / `VirtualCam` / `HikRobotCam` 平级，共享 [[api/ICameraRun]] 统一契约；实现类 `IntelligentLaserCameraRun` **无缝接入** `LineLaserWorkflow` 取图链（无需改工作流代码）。

## 关键事实

- **三态精简 + UI 状态本地化（2026-08-25）**：① 状态精简为线激光三态 `isConnected`（`_isConnected`）/ `isLaserOn`（`_isLaserOn`）/ `isCameraOn`（`_isCameraOn`），删除冗余 `_isRunning`/`_isOpened` 字段与 `IlHardwareStatus` 快照类；`IsRunning`（ICameraRun 接口）派生自 `_isCameraOn`。② `IsLaserOn()`/`IsCameraOn()` 改为**本地状态读取**：连接成功时 `SyncHardwareStatus()` 从硬件同步一次（"第一次正确"），`SetLaser`/`SetSensor` 操作成功后本地更新，UI 点击立即生效，不再每次读硬件（消除硬件查询延迟导致的"越点越乱"）。③ **用户澄清：`StCtrl.DwCameraEnable` 由 `SetSensor(bool)` 控制**——`IsCameraOn()` 即传感器/相机状态真相源。④ `DetectHardwareStatus()` 更名为 `SyncHardwareStatus()`（无快照，直接同步本地字段 + `_scanRateHz`）。⑤ `ILCamPage` 连接态改以 `_ilCamera.IsConnected` 为真相源（独立调试页不再依赖 LineLaserWorkflow 状态机，修复"相机已连仍显示未连接"）；构造函数/连接成功/进入自动模式均只同步一次硬件。
- **Job 参数按接头类型过滤（2026-08-25）**：`IlJointTypeInfo` 新增 `DisplayKeys`（jointtypelist.json 的 `display` 键集，技术员确认的该接头类型 Job 实际使用参数）；新增 `GetJointTypeDisplayKeys(int)` API；`ILAlgoPage.RefreshJobParams` 按当前 Job 的 jointtype 过滤参数表。**2026-08-25 修正匹配策略**：display 键带 `params_` 前缀、SDK 参数名不带（`inspect_`/`baseline_`/`segment_`/`camera_` 前缀）→ 改为词级匹配（去前缀相等 + 词级后缀/前缀），**过滤后为空回退全显**（避免参数表空白）；**ILCamPage 订阅 `JobParamsChanged` 同步 cmbJob 下拉**（ILAlgoPage/工作流切 JOB 后主 UI 自动刷新）。

- **同步初始化 + 初始化校验简化 + 安全默认态 + 日志净化 + UI 同步完善 + 重复状态转换修复（2026-08-20）**：① **同步初始化**：`LineLaserWorkflow` 新增 `InitializeSync()` 同步方法，阻塞等待四步初始化完成；`DeviceControlWork`（原 `MainDeviceThread`）子设备初始化改为同步顺序执行（一个完成才开始下一个），线激光不再走异步线程。② **初始化校验简化**：第 4 步 `verifyHardwareStatus` 从「连接+传感器运行+校准数据（等3秒）」简化为**仅校验连接成功**——连接上就是正常的。校准数据通过 `InternalRefCornerPts` 异步回调到达，属运行时状态，不阻塞初始化；传感器在第 3 步启动，保持运行以接收轮廓回调。③ **安全默认态**：初始化校验通过后立即关激光（`SetLaser(false)`）、关相机（`SetCaptureCamera(false)`），确保硬件进入安全待机态；传感器保持运行（画面才能正常显示轮廓）。④ **日志净化**：去除 `----` / `====` 符号分割线，改用纯文本步骤描述。⑤ **UI 同步完善**：移除 `ILCamPage` 构造函数中强制跳转状态机的逻辑（会干扰正式初始化流程），改为：初始化过程中由 `OnIlStateChanged` 监听 `Initializing→Standby` 转换并调用 `SyncFromHardwareAfterConnect()`；若页面在初始化完成后才打开（状态已 Standby），构造函数直接调 `SyncFromHardwareAfterConnect()` 做一次性同步。⑥ **重复状态转换修复**：`LineLaserWorkflow.Initialize()` / `InitializeSync()` 中多写了一行 `_deviceStateMachine.TryTransition(Initializing)`，而 `_deviceStateMachine.Initialize()` 模板方法内部第一步也会做这个转换，造成 `Initializing→Initializing` 非法转换 → 初始化立即失败。修复：移除工作流层的重复转换，设备状态机的 Initializing 转换统一由模板方法负责。见 [[modules/DeviceControl]]、[[modules/DeviceControl]]、[[lessons/StateMachine-DoubleTransition]]。
- **按钮语义修正 + 连接后帧率同步 + 手动/自动数据流分离（2026-08-20 Bug 修复）**：① **按钮语义修正**：「开启相机」按钮从控制 `SetCaptureCamera`（采集相机上电）改为控制 `SetSensor`（传感器使能=回调源头），开启时顺带确保采集相机上电；激光按钮仅控激光，与相机完全解耦。连接后不再自动开启传感器（移除 `SyncFromHardwareAfterConnect` 中的 `SetSensor(true)`），由用户手动点击「开启相机」控制。`UpdateFpsDropdownState` 和 `btnApplyFps` 的帧率切换保护从 `IsCaptureCameraOn()` 改为 `IsSensorRunning()`。变量 `_isCaptureCameraOn` 重命名为 `_isCameraOn`，语义为「用户视角的相机开关=传感器是否运行」。② **连接后帧率同步**：`DetectHardwareStatus()` 读取硬件实际 FPS 后同步更新内部 `_scanRateHz` 字段，解决「连接后 ScanRateHz 仍为默认 60Hz，显示帧率与实际档位不符」问题。③ **手动/自动数据流分离**：`ILCamPage.RefreshDisplay()` 仅在手动/空闲模式下绘制 Mat 和结果表；自动模式（工作流运行中）直接返回不刷新页面——轮廓数据通过 `ContourDataReady` 事件外传至主页面 ScottPlot，焊缝特征点和宽度传至自动调整计算。移除原「自动显示」`swDisplay` Switch 控件及相关逻辑（构造订阅/销毁取消订阅/CheckedChanged 事件/UpdateModeUi 中使能控制）。
- **UI 细化调整（2026-08-20）**：① **双帧率显示**：结果面板顶部三个 label — 左「轮廓点」、中「传感器帧率」（`ScanRateHz`，采集分析频率，硬件目标帧率）、右「回调帧率」（`MeasuredFps`，实际收到回调的帧率）。原中间 `label1` 重命名为 `lblSenorfps`，文本从"实测帧率"改为"传感器帧率"；右侧 `lblMeasuredFps` 文本从"实测帧率"改为"回调帧率"。② **swDisplay 语义调整**：从「自动模式下是否显示」改为「手动模式下是否绘制 Mat」——手动模式勾选时显示画面，取消时只看结果表（降低 GPU/CPU 占用）。自动模式下 switch 禁用（自动模式本页不绘制，数据外传）。标签文字从"自动显示"改为"显示画面"。③ **结果表列宽缩短**：`dgvResult` 列宽从 200/300/120 调整为 120/160/70（字段/值/单位），适配面板宽度。④ **按钮文字统一**：`btnCaptureCamera` 文字从「开启相机/关闭相机」改为「开启传感器/关闭传感器」，避免用户将"相机"误解为采集相机电源而非传感器采集；断开连接重置文字、帧率切换保护提示同步更新。
- **传感器帧率实时刷新 + FetchFpsModel 日志（2026-08-20 修复）**：① **传感器帧率运行时实时刷新**：`MillionOutlineCallback` 中新增节流式 `FetchSensorFps` 调用（每 500ms 一次），周期性更新 `_scanRateHz`，使 `ScanRateHz` 属性反映传感器运行时的实时采集分析频率（不再只在连接/设置时各读一次）。配合 `ILCamPage.RefreshDisplay` 中已有的 `ScanRateHz` 读取，`lblSenorfps` 实时显示传感器硬件输出的帧率值，可用于判断传感器是否达到设定帧率档位。节流参数：`SensorFpsUpdateIntervalMs = 500`，兼顾实时性与 SDK 硬件查询开销。② **FetchFpsModel 失败日志**：`FetchFpsModel()` 从静默失败改为输出 warning 日志（SDK 返回值 + 异常信息），方便排查「连接后帧率下拉仍显示标准模式」的问题——若 `FetchSensorFpsModel` 调用失败（如传感器未运行时读不到、dwInstanceId 参数不对、枚举值不匹配等），可从日志中确认返回码与异常原因。
- **dwInstanceId 参数统一修复（2026-08-20 根因修复）**：所有 SDK 函数的 `dwInstanceId` 参数从混用 `0u`/默认值统一改为 `1u`（SDK 默认值）。**根因**：英莱 SDK 中 `FetchSensorFps`、`FetchSensorFpsModel`、`FetchSensorInfo` 等函数的 `dwInstanceId` 默认值为 1，实例 0 未初始化，调用时返回 `INTELLIGENT_E_UNINIT (0x1000000)`。**影响**：修复前 `IsSensorRunning` 可能始终返回 false、`FetchFpsModel` 失败回退 STANDERD、`ScanRateHz` 实时刷新失效、`DetectHardwareStatus` 读不到帧率。**修复范围**：5 处 SDK 调用（`FetchSensorInfo`×1、`FetchSensorFps`×3、`FetchSensorFpsModel`×1）全部由 `0u` 改为 `1u`。回调注册等使用默认值的调用不受影响（本身就是 1）。
- **回调重构 + CommPeriod 默认配置（2026-08-20）**：① **回调两步结构重构**：`MillionOutlineCallback` 重构为「第一步拿数据 → 第二步模式分支」的清晰结构。第一步（所有模式共用）：原生数据读取、轮廓点计数、实测 FPS 计算、传感器 FPS 刷新（500ms 节流）、PointCloudData 构建、InspectResult 捕获。第二步（模式分支）：手动模式生成 Mat + 换帧 + 触发 `ContourFrameReady` UI 事件；自动/其他模式仅外传 `ContourDataReady` 事件，不生成 Mat、不触发 UI，节省 CPU/GPU 开销。新增 `IsManualMode` 属性（默认 true）控制模式切换，`ILCamPage.UpdateModeUi` 中根据工作流状态自动设置。减少临时变量：移除 `var contour` 中间引用，`newMat` 仅在手动模式分支内分配。② **传感器帧率标签修复**：`ILCamPage.RefreshDisplay` 中轮廓点 + 传感器帧率 + 回调帧率三个状态标签的更新移到模式判断之前，自动模式下也能实时显示帧率数值。③ ~~`ConnectCore` 连接成功后调用 `SetSensorCommPeriod`~~ → 改为 `ConfigureDefaultCommPeriod()` 初始化专属方法。
- **CallbackOnCollectedDelegate 根治 + CommPeriod 初始化专属 + 线激光工作流分步重构（2026-08-20）**：① **回调委托只注册一次**：新增 `_sdkInitialized` 标志，首次连接才 InitSDK + RegisterCallbacks，重连仅 ConnectToSensor；`DisconnectManual` 不再 UnInitSDK / Free 委托 / Free hostHandle，仅关外设+断连；仅 Dispose 时完整释放。从根本上避免频繁开关相机导致的委托 GC 回收（与英莱 demo 做法一致）。② **CommPeriod 初始化专属配置**：新增 `ConfigureDefaultCommPeriod()` 公共方法 + `_commPeriodConfigured` 标志，仅在 `LineLaserWorkflow.InitializeWorker` 初始化成功后调用一次，手动连接/重连不重复配置。③ **线激光工作流分步重构**：见 [[modules/DeviceControl]] 和 [[decisions/ADR-035-LineLaserWorkflowRefactor]]。

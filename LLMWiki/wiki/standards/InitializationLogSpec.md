# 初始化日志规格（InitializationLogSpec）

> **触发**：改动整机初始化的任何 `Log(...)` 文案、级别、顺序，或新增初始化节点/阶段时，AI **先读本页再改码**，⛔ 不自行发明「三重开始 + 路径全量 + 汇总后补尾巴」的写法。
>
> **适用范围**：`MainDeviceControl/DeviceControlWork.cs`（节点驱动与汇总）、`MainDeviceControl/DeviceWorkflow/*`（各模组连接日志）、`MotionControl/MontionManager.cs`（使能日志）、`Comm/Communication/*`（通讯层日志）。

---

## 一、一句话判据

> **一个事实只留一条权威行；汇总必须是最后一条；连接与使能分成两个阶段，前一个失败后一个只报一句跳过。**

---

## 二、层级与命名口径（写死）

| 层级 | 名称 | 数量 |
|---|---|---|
| **独立模组** | 机器人通讯 · 运动控制器 · 线激光相机 · 监控相机 | 4 |
| **运动控制器下属** | 焊接头从站 · 轴从站（Y / TA / LA） | 随配置 |

- ⛔ **禁止使用「子设备」**：它们不是独立设备，是本设备下的**模组**。
- 初始化节点表固定 5 项（含「焊接头从站」），编号 `[1/5]`~`[5/5]` 恒定输出。
- 英文标识（`SubDeviceState` / `SubDeviceWeldStatus` 等）**不改名**，只改中文文案。

---

## 三、四段式文案（启动 → 动作 → 成功/失败 → 原因）

单个模组：**正常 ≤3 行，失败 ≤4 行**。

| 阶段 | 唯一文案模板 | 级别 | 必打 |
|---|---|---|---|
| 阶段一开头 | `模组初始化开始 阶段一 连接 共 {N} 个模组` | Info | 是 |
| 模组启动 | `[{i}/{N}] {模组} 连接 开始` | Info | 是 |
| 模组成功 | `[{i}/{N}] {模组} 连接 成功` | Info | 是 |
| 模组失败 | `[{i}/{N}] {模组} 连接 失败 原因 {原因}` | Error | 是 |
| 模组跳过 | `[{i}/{N}] {模组} 连接 跳过 原因 {父级} 未就绪` | Warning | 是 |
| 未启用 | `[{i}/{N}] {模组} 连接 跳过 原因 未启用` | Warning | 是 |
| 阶段二开头 | `阶段二 使能 开始` | Info | 就绪时 |
| 阶段二逐轴 | `阶段二 使能 {轴} 成功` / `阶段二 使能 {轴} 失败 状态字 0x{XXXX}` | Info / Error | 就绪时 |
| 阶段二跳过 | `阶段二 使能 跳过 原因 连接阶段运动控制器未就绪` | Warning | 未就绪时 |
| 阶段二完成 | `阶段二 使能 完成 成功 {X} 失败 {Y}` | Info / Error | 就绪时 |
| 回零 | `初始化回零 {轴} 成功 用时 {s}s 起 {a}mm 终 {b}mm` / `初始化回零 {轴} 失败 {原因}` | Info / Warning | 就绪时 |
| 工作零位 | `TA 零位 完成 目标 {mm} 容差 {mm}` | Info | 就绪时 |
| 轴闸门 | `轴闸门 {TA/Y/LA} 打开/关闭 {原因}` | Info / Warning | 就绪时，**汇总前** |
| 汇总（最后一条） | `初始化汇总 成功 {X} 失败 {Y} 跳过 {Z}` | Info / Error | 是 |
| 顺序明细 | `初始化顺序 …` | Debug | 否 |
| 配置回显 | `流程超时生效 …` / `设备侧等待生效 …` | Debug | 否 |
| 板卡明细 | `主站打开成功 检测到板卡 {n} 张` | Debug | 否 |
| 路径明细 | `机器人端 RSI XML 配置已生成 {绝对路径}` | Debug | 否 |

失败原因必须**具体到可操作**：`本机未找到该 IP` · `未检测到板卡` · `厂商返回码 0x3F（Core 服务未连上）` · `未枚举到海康相机`。⛔ 不允许只写「失败」。

## 四、四条硬约束

### R1 阶段分离

- **阶段一 连接**：逐模组 `连接 开始/成功/失败/跳过`。
- **阶段二 使能**：**仅当连接阶段运动控制器就绪才展开**（逐轴、逐门禁打日志）。
- 运动控制器未就绪 ⇒ 阶段二**只打一条** `阶段二 使能 跳过 原因 …`，⛔ 不得逐轴/逐门禁铺开。
- ⛔ 禁止出现「初始化第 2 步 / 第 3 步」这类不带阶段名的裸编号（统一为 `阶段二 使能 …`）。

### R2 汇总收尾唯一

- `模组初始化汇总` 必须是整个初始化序列的**最后一条**日志。
- `轴闸门`、`TA 轴降级`、`整机轴汇总` 等尾巴信息**一律前移**到汇总之前。
- ⛔ 汇总之后不允许再出现任何 `Log(...)`。

### R3 编号恒定 + 事实唯一

- 5 个节点编号恒定输出，**跳过也占位**（不允许 `[2/5]` 直接跳到 `[4/5]`）。
- 同一事实只保留一条权威行；各工作流/设备层的同义日志**降 Debug**（诊断价值保留在日志文件里，但不刷屏）。
- ⛔ 禁止「未启用」也算成功；`通道就绪` / `连接受理` 都不是 `连接成功`，成功判据必须是**监听/握手真正启动**。

## 五、审查判据（脚本）

| 判据 | 脚本 | 触发 |
|---|---|---|
| 初始化链按父级门禁驱动，父未就绪不发起连接 | `scripts/csharp_review.py` → `C.设备初始化分层` | 定义 `InitializeMachineTick` 的文件 |
| 汇总后仍有同类日志 / 「子设备」残留 | `scripts/csharp_review.py` → `D.初始化日志` | 定义 `FinishInitialization` 的文件 |
| 自动刷新开关默认关闭 | `scripts/csharp_review.py` → `B.刷新默认开` | `SystemControlPage.Designer.cs` |

`D.初始化日志` 的三条具体检测：

1. 出现 `"子设备` 字符串字面量 ⇒ 告警（应改「模组」）。
2. `LogAxisGateReport` 出现在 `模组初始化汇总` 之后 ⇒ 告警（汇总不再收尾）。
3. `模组初始化汇总` 所在行之后仍有 `Log(` ⇒ 告警（收尾不唯一）。

## 六、极简密度（2026-11-11 业主追加，最高优先级）

> **事实验收**：初始化 Info 日志只回答三件事——**执行哪一步、成还是败、失败原因（带状态码）**。
> 其余一律不写；写了就是回潮。

### 6.1 合格样例（照这个密度写）

```text
[2/5] 运动控制器 连接 开始
[2/5] 运动控制器 连接 失败 未检测到板卡
[3/5] 线激光相机 连接 失败 返回码 0x3F
阶段二 使能 TA 成功
阶段二 使能 Y 失败 状态字 0x0000
阶段二 使能 完成 成功 1 失败 1
初始化回零 TA 失败 等待回零超时 120s 起 1.234mm 当前 1.234mm
初始化回零 TA 成功 用时 4.2s 起 0.000mm 终 -12.345mm
TA 零位 完成 目标 0.000mm 容差 0.100mm
初始化汇总 成功 3 失败 2 跳过 0
```

### 6.2 七类必删内容

| 类别 | 反例 | 处置 |
|---|---|---|
| 文件路径 | `D:\...\Config\...xml` | Info / Debug 均不出现；改用相对标识或整条不打 |
| 排查建议句 | `常见于驱动器未上电、网线/节点号不匹配…` | 整句删除，只留结论 |
| 可能性说明 | `状态字 0x0000 的官方定义未确证` | 删除；`DescribeAxisDiagnosis` 只进 Debug |
| 重复修饰 | `下发 无（指令未下发或被前置拦截）` | 只留结论 |
| 括号长解释 | `关闭（TA 未回零（伺服下电后位置不可信…））` | 改为 `关闭 TA 未回零` |
| 括号内变量名 / 配置键 / 来源 | `-30.000mm（TA_ZERO_POSE_MM）`、`10.000mm/s（轴运行速度 MaxVel）` | 只留数值，来源进 wiki，不进日志 |
| 参数/配置回显 | `指令检测 5.0s 采样 20ms … 主站初始化 30s`、`轴 2 个 输入 0 个…` | 降 Debug 或合并为一条极短 |

### 6.3 密度判据

1. **一条一行、不跨行、不追加第二句**；中文部分目标 ≤30 字。
2. 失败行**必须带原因**；有状态码/返回码/`Home_Status` 就带，十六进制。
3. 明细级诊断（`DescribeAxisDiagnosis`、超时参数、配置计数）**只能 Debug**，⛔ 不进初始化 Info。
4. `初始化汇总` 仍是最后一条；回零/零位行都在它之前。
5. ⛔ 禁止在 Info 行里拼「因为…所以…请检查…」的因果解释；解释放 Debug 或 wiki。

### 6.4 防回潮判据

> 改动初始化日志后，对每个 Info 行问一句：**这行删掉会不会让人不知道「哪步、成没成、为什么」？**
> 不会 ⇒ 删或降 Debug。会 ⇒ 保留，但不得追加第二句。

### 6.5 显示端按级别过滤（2026-11-11 业主追加）

> **等级不是写完就算，显示端必须真的过滤。**

| 端 | 行为 |
|---|---|
| 界面日志区 | 恒显示 `Info / Warning / Error`；`Debug` 默认**不显示** |
| Debug 开关 | `Config/Comm/CommunicationSettings.ini` → `[Display] ShowDebugLog=true`（默认 false，改后重启生效） |
| 文件日志 | 四级**全量**写入，供事后排障，不受界面开关影响 |

- 唯一显示入口 = `GlobalCommData.ShowLog`；⛔ 禁止绕过它直接往界面追加日志。
- 新增日志若"只有开发想看"，必须用 `MessageLevel.Debug`，并确认界面按级别丢弃。
- 判据：默认配置启动一次，界面**不得出现任何 Debug 文案**（SDO 探测、基线读、配置明细、超时参数、路径等）。

### 6.6 配置回显只进 Debug

以下内容一律 `MessageLevel.Debug`，不得进初始化 Info：

- 轴数 / 输入输出数 / 气缸数 / 焊接头装载状态
- 卡号 / 板卡数 / 从站数量 / 主站初始化完成
- `TA 轴已按 … 装载特有参数 …`、`按配置创建 …`、`已向控制器注册 …`
- 流程超时、采样周期、等待时长等参数罗列

### 6.7 同一事实唯一行

| 事实 | 唯一权威行 | 其余处置 |
|---|---|---|
| 回零成功 | `初始化回零 {轴} 成功 用时 … 起 … 终 …` | 轴内"回零完成"、等待层"TA 回零完成"→ Debug |
| 模组连接 | `[{i}/{n}] {模组} 连接 成功/失败/跳过 …` | 模组内部连接过程 → Debug |
| 初始化收尾 | `初始化汇总 成功 X 失败 Y 跳过 Z` | 不再打「整机初始化 部分完成」 |

判据：同一次启动里，同一事实出现两条及以上且都在 Info ⇒ 违规。

## 七、反例（业主要求一次改好的原始问题）

```text
RSI 监听启动失败 本机无可用网口承载 HOST_IP 192.168.10.50（本机未找到该 IP）
机器人通讯监听结果 False
机器人通讯监听启动失败，待机重试
机器人通讯 成功 通讯通道已开启            ← 判成功，错（通道就绪≠连接成功）
...
初始化步骤 1/3 连接设备                     ← 三重开始
连接开始
初始化连接开始
线激光相机 连接失败 …                       ← 同一事实三次
线激光相机 失败 …
...
整机初始化 全部完成（成功 0 轴）            ← 汇总提前
轴闸门 TA 关闭                              ← 汇总后的尾巴
TA 指令区不可用
```

反例的四个病根：**误判成功 · 阶段混用 · 编号断裂 · 汇总不唯一**。改后同场景 55 行 → 15 行（含启动 3 行）。

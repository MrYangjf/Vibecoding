# C# Vibecoding 代码审查

针对 .NET Framework 4.8 / C# 7.3 项目，从单个 `.cs` 文件入手，检测 AI 辅助编程（vibecoding）常见的冗余问题。

## 边界约束（不可违反）

1. **只处理单个 `.cs` 文件**，不跟踪项目引用、不跨文件分析。
2. **不处理 `*.designer.cs`**（设计器自动生成文件直接跳过）。
3. **不延伸到外部引用文件**——发现问题只在当前文件内解决。
4. **不修改对外函数接口**：public/protected 方法签名（名称、参数、返回类型）不变。
5. **不修改对外变量名称**：public 属性/字段名不变。
6. 修复时优先改动 private 成员；涉及 public 成员的问题只报告不自动改。

## 工作流程

### 第 1 步：运行扫描脚本

对目标文件执行静态扫描脚本，获取机械检测结果：

```bash
python3 <skill_dir>/scripts/csharp_review.py <目标文件.cs> --verbose
```

脚本输出按类别分组的问题清单（含行号、严重级别、代码片段），支持 `--json` 输出。脚本只做启发式标记，**不代表最终结论**——需结合业务语义判定。

### 第 2 步：逐类人工审查

脚本扫描后，对照以下三类规则逐项确认。规则页与本页同在 `wiki/standards/`（平铺，无子目录），审查时按需读取：

| 类别 | 规则页 | 核心内容 |
|------|--------|----------|
| A. 文件书写整理 | [[standards/CodeSimplification-RefFileOrganization]] | 成员顺序、#region 划分、XML 注释规范 |
| B. 代码逻辑精简 | [[standards/CodeSimplification-RefLogicSimplification]] | 9 类禁止项及 AI 高频反例 |
| C. 函数精简 | [[standards/CodeSimplification-RefFunctionSimplification]] | 功能重叠合并、嵌套内联、死函数 |

**A 类检查要点**：
- 成员顺序：私有变量 → 公共变量 → 构造函数 → 私有函数 → 公共函数
- 每个区域用 `#region`/`#endregion` 包裹，region 名用中文类型名
- `public`/`protected` 方法**新增或改动必写** `///`（存量欠账不追溯，不设全库清零目标）；`private` 方法**允许且建议写** `///` 做总结（不强制，且**不得据此删除既有 private `///`**）；无论公私，写了就要 summary 一行 + param/returns 完整
- `/// <summary>` 20 字内，只说"做什么"不写过程；每个 `<param>` 有实质说明；有返回值写 `<returns>`

**B 类检查要点**（9 项禁止，每项在 references 中有 AI 常犯错误展开）：
1. 优先用类私有变量，控制临时变量
2. 禁止无意义 null 判断
3. 禁止无意义安全锁
4. 禁止无意义函数值赋值传递
5. 禁止过度使用枚举
6. 禁止过度设定属性
7. 禁止过度等待/延迟
8. 禁止过度缓存数据
9. 禁止过度资源管理

**C 类检查要点**：
- 功能重叠：同簇方法（去 V2/Ex/With 后缀后同名）token 相似度 ≥50% 标记为合并候选
- 嵌套内联：private 方法仅被 1 处调用、方法体 ≤3 行、无复杂控制流 → 内联到调用方
- 死函数：private 方法本文件内零调用且无委托/事件/nameof 引用 → 确认后删除

### 第 3 步：输出审查报告

报告格式：

```
## 代码审查报告：<文件名>

### 必须修改（错误/警告）
- 行 N: [类别] 问题描述 → 修改建议

### 建议优化（提示）
- 行 N: [类别] 问题描述 → 修改建议

### 确认后修改（涉及 public 成员）
- 行 N: [类别] 问题描述 → 建议方案（需确认外部无调用）
```

### 第 4 步：执行修复（用户确认后）

用户确认报告后，按约束执行修复：
- 先改 A 类（region 重排、注释补全/删除）——机械性修改，风险低
- 再改 C 类（合并/内联/删除 private 方法）——需逐处确认调用关系
- 最后改 B 类（删除冗余 null 检查、锁、临时变量等）——需理解业务逻辑
- public 成员的问题只标注，不自动修改
- 修复后重新运行脚本验证警告清零

## 严重级别说明

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| 错误 | 确定的 bug 或严重违规（如 `lock(new object())`） | 必须修改 |
| 警告 | 高概率冗余，需确认后修改 | 逐条确认 |
| 提示 | 可能的问题或风格建议 | 按需处理 |

## C# 7.3 语法注意

- 不使用 C# 8+ 特性：可空引用类型（`string?`）、switch expression、record、using 声明、nullable enable
- 自动属性只读写法用 `{ get; }`（C# 6+ 支持，7.3 可用）
- 异步用 `async/await`（C# 5+ 支持），但不要用 `Task.Run` 包装同步方法伪造异步

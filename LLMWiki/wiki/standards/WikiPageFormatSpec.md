# Wiki 页面格式规范（强制）

> **一句话**：本规范定义 LLMWiki 每一类页面的**结构契约**——每个页面**只能写什么、写到多长、怎么增长**，以及**用什么脚本生成/校验**。
> **配套工具**：`tools/wiki_format.py`（格式校验）· `tools/wiki_index_build.py`（索引重建）· `tools/wiki_log.py`（日志写入/截断）· `tools/adr_new.py`（ADR 新增/合并）· `tools/lesson_new.py`（教训新增/合并）。
> **强制条款**：⛔ 本规范由 `tools/wiki_format.py` 在 Phase 4 机械校验，违规非零退出；⛔ 任何页面**不得手工编写应由脚本生成的结构化区块**（索引表、编号表、日志条目）。

---

## 一、总原则（四条）

| # | 原则 | 反面（禁止） | 正面（要求） |
|---|---|---|---|
| 1 | **一表一源** | 同一份数据在两处各写一遍（如 index.md 与 ADR-Index 各存 ADR 总表） | 唯一权威页持有数据，其他页只放**指针**（`[[decisions/ADR-Index]]`） |
| 2 | **摘要不长编** | 索引/表格单元格里塞进决策史、日期沿革、删除过程 | 单元格 = **一句话职责**（≤120 字符）+ 指向权威页的链接 |
| 3 | **叙事只进 log** | 把「当时怎么查的、试错几次、改了哪几行」写进 wiki 页 | 详细过程写 `logs/log.md`；wiki 页只留**结论与约束** |
| 4 | **结构靠脚本** | 手工插表格行、手工算计数、手工写日志条目 | 脚本生成 + 脚本校验；手工只写**散文与判定** |

## 二、页面分类与结构契约

### 2.1 `wiki/index/index.md` —— 路由索引（薄）

**唯一职责**：让人/AI 在 30 秒内定位到「该读哪一页」。**不承载任何详情**。

允许的章节（**顺序固定**，缺项即违规）：

| 顺序 | 章节 | 内容契约 | 行数上限 |
|---|---|---|---|
| 1 | `# Wiki Index` + 抬头 blockquote | 一句用途 + 「最后更新」元数据（**仅此一处允许出现日期**） | ≤6 |
| 2 | `## ⚡ 场景速查路由` | **每行 = 一个任务场景**；第 2 列 = 直接该读的 1~3 页；第 3 列 = 硬约束提示（**≤80 字符**） | ≤60 |
| 3 | `## 目录` | 十类章节的跳转表，每行 ≤100 字符 | ≤20 |
| 4 | `## 一、项目总览` … `## 十、来源索引` | 每类一张表：**页面链接 / 一句话摘要（≤120 字符）/ 标签** | 每节 ≤40 |
| 5 | `## 维护说明` | 工具脚本清单 + 校验命令 | ≤30 |

**硬约束**：
- ⛔ 全文 **≤600 行 / ≤80 KB**；超限即拆分类明细页（`wiki/index/<类别>.md`）。
- ⛔ 表格**摘要列（第 2 列）**与**分类明细表**不得出现 `YYYY-MM-DD` 日期串（日期只在抬头与 log）。
  ✅ **例外**：速查路由表的**第 1 列（场景描述）允许含日期**——它是检索线索（如「运控 2026-09-07 换轨」）；但**第 3 列（硬约束提示）严禁**。
- ⛔ **不得**内嵌 ADR 全量表（唯一权威 = [[decisions/ADR-Index]]）、不得内嵌历史编号映射表。
- ⛔ 速查路由表**第 3 列 ≤80 字符**；摘要列 **≤120 字符**。
- ⛔ 索引中**不得**出现删除线（`~~`）与「已废弃/已删除」叙述 → 这类内容属 log 或 ADR-Index。
- ⛔ **同一页面不得在两节各列一次**（`wiki_audit.py` §3 判重复）。`project/` 页对「§一 项目总览」与「§八 历史归档」**互斥归属**：
  - §一 = 现行有效的主线页（概览 / 架构 / 工作流规范 / Skill 体系演进）；
  - §八 = 台账 / 过程 / 审计 / 进度快照类（只追溯，不作编码约束）。

  归属白名单写在生成器常量 `ARCHIVE_PROJECT`（`tools/wiki_index_build.py`）——**不手工改 index.md**，改归属只改该常量后重跑生成器。

### 2.2 `wiki/decisions/ADR-NNN-{Slug}.md` —— 架构决策

**唯一职责**：记录**一个决策**——为什么这么定、定了什么、代价是什么。

**结构契约**（章节顺序固定）：

```
---                                   ← frontmatter（字段见下）
title: ADR-NNN <一句话标题>
date / updated / status / tags
---

# ADR-NNN <标题>

> **决策一句话**（≤120 字符，读者只看这行就能用）

## 背景            ← 为什么需要这个决策（≤8 行）
## 决策            ← 定了什么，编号条目（≤12 条，每条 ≤100 字符）
## 备选方案        ← 考虑过什么、为什么放弃（≤4 条）
## 后果            ← 正面 / 负面（各 ≤5 条）
## 相关页面        ← [[...]] 链接
```

**frontmatter 契约**：`title` 必须含自身编号；`date`/`updated` 为 `YYYY-MM-DD`；`status` ∈ {proposed, accepted, deprecated}；`tags` 为关键词数组。

**硬约束**：
- ⛔ 单决策页 **≤200 行**；⛔ **整合页 ≤300 行**（含 `merged_from` / 沿革 / 被推翻的中间态的合并页放宽）。
- ⛔ `## 决策` 每条**≤100 字符**（禁止整段叙述）。
- ⛔ **禁止**在 ADR 页内写「试错过程 / 改了哪几行 / 静态检查 N/N / 探针实测数据」→ 属 log。
  ✅ 但**方法论约束**（如「Span 行为一律实测，不以官方文档为准」）属决策内容，应保留。
- ⛔ **禁止**在 ADR 页内写「YYYY-MM-DD 决定…」式日期沿革流水（决策日期已在 frontmatter）。
- ⛔ 同类决策**不得**新建页 → 见 §三 增长规则。

### 2.3 `wiki/lessons/{Topic}.md` —— 教训门禁

**唯一职责**：记录**一个可复现的坑**，让下次编码能避开。

**单坑页结构契约**：

```
--- (title / date / updated / status / tags) ---
# <标题>

> **一句话**：什么坑（≤120 字符）

## 现象        ← 症状：看到什么（≤6 行）
## 根因        ← 为什么（≤6 行）
## 判据        ← 怎么判定（可机械检查的句子/命令，≤8 行）
## 预防        ← 今后怎么做（≤6 条，每条 ≤100 字符）
## 相关页面    ← [[...]]
```

**多坑页结构契约**（同族多坑合并到一页时）：
- 一级标题 + `> 一句话` 总述；
- 每个坑一个 `## 坑 N：<标题>`，其下用 `### 现象 / ### 根因 / ### 判据 / ### 预防`；
- 末尾 `## 相关页面`。

**硬约束**：
- ⛔ 单坑页 **≤250 行**；⛔ 多坑页 **≤700 行**（超限 ⇒ 拆分主题）。
- ⛔ 单坑一页；⛔ 同族坑**不得**新建页 → 追加到既有同族页的「## 追加条目」小节。
- ⛔ 禁止把整页写成流水账（多坑混记）→ 应拆成多页或按主题合并。

### 2.4 `wiki/{modules,api,guides,standards,project,people,architecture}/` —— 各类说明页

| 类别 | 一句话职责 | 摘要上限 | 全文上限 |
|---|---|---|---|
| `modules/` | 模块边界与协作 | 120 字符 | 400 行 |
| `api/` | 公共契约（签名/事件/返回值） | 120 字符 | 400 行 |
| `guides/` | 怎么做（操作手册） | 120 字符 | 500 行 |
| `standards/` | 必须遵守的规范 | 120 字符 | 500 行 |
| `project/` | 项目级台账/审计/进度 | 120 字符 | 400 行 |
| `people/` | 专员职责 | 120 字符 | 150 行 |
| `architecture/` | 架构真相源 | 120 字符 | 800 行 |
| `rules/` | **Skill 流程执行强制规则**（原 Skill Key Rules 的下沉处；编号 `KR-001~` 连续） | 120 字符 | 150 行 |

### 2.4b `wiki/rules/KR-NNN-{Slug}.md` —— Skill 流程执行强制规则

**唯一职责**：记录**一条流程执行规则**——规定「AI 在跑这个工作流时该怎么做」。

**边界判据（2026-11-02 收敛）**：

| 规则类型 | 归属 | 例子 |
|---|---|---|
| **流程执行类** | ✅ 留在 `rules/` | 强制执行顺序 · 步骤级展示 · 不得跳过 Query · Ingest 强制 · backup/output 时机 |
| **内容 / 技术类** | ⛔ 归 `lessons/` | csproj 注册 · 行尾守恒 · 锚点构造 · 并发 Edit · 零消费≠死成员 |
| **格式规范类** | ⛔ 归 `standards/` | 页面结构 · 行数上限 · 摘要长度 · 增长规则 |
| **决策类** | ⛔ 归 `decisions/` | 为什么这么定 · 废止不回收编号 · 旧号消歧 |

**为什么这样分**：两类规则的**失效后果不同** —— 流程类失效 = 工作流跑偏（漏查、跳步、谎报）；内容类失效 = 写错代码 / 知识库漂移。混在一处会让「查流程规则」变成「查技术判据」，检索路径混淆。

**结构契约**（章节顺序固定）：

```
--- (title 含 KR-NNN / date / updated / status / tags) ---
# KR-NNN <短标题>

> **一句话规则**（≤120 字符，读者只看这行就能遵守）

## 适用范围    ← 何时必须遵守 / 何时不适用（必填）
## 规则正文    ← 编号条目（每条 ≤200 字符；⛔ 禁止整段散文）
## 判据        ← 可机械检查的判定句 + 校验命令（≤8 行）
## 反例        ← 违规写法 → 正解（表格，≤4 行）
## 相关页面    ← [[...]]，必须回链 [[rules/Rules-Index]]
```

**硬约束**：
- ⛔ 单页 **≤150 行**；⛔ 编号**连续无空洞**，新号 = `Rules-Index` 中 `max+1`，⛔ **废止不回收编号**。
- ⛔ **同主题一律合并**进既有页（追加「## 演进记录」），**不新建页** —— 与 ADR 同规则（§三）。
- ⛔ 规则正文**不得**含验证叙事（静态 N/N · 阴性对照 · 探针实测）→ 属 log。
- ⛔ 规则正文**不得**含技术细节（代码写法 · 脚本陷阱 · 行尾 / 编码判据）→ 属 `lessons/`。
- ⛔ **Skill 里不得维护规则清单** —— 规则正文只在本类目，Skill 只写「去哪查」。

### 2.5 `logs/log.md` —— 唯一允许详细的载体

**唯一职责**：按时间倒序记录**每一次变更的过程与证据**。

**条目契约**：

```
## [YYYY-MM-DD HH:mm:ss] <op> | <一句话标题>
- 来源：<用户指令 / 触发原因>
- 操作：<编号列表>
- 变更文件：<...>
- 结论 / 遗留：<...>
```

- **新增条目只能由 `tools/wiki_log.py append` 写入**（时间戳由脚本取，禁止手填）。
- **条目数上限 50**；超出由 `tools/wiki_log.py truncate` 截断 —— 旧条目**按日期归档**到 `logs/backup/log_YYYY-MM-DD.md`（⛔ **截断是归档不是丢弃**），并**自动重建** `logs/INDEX.md` 归档索引（一行一天）。⛔ **log 截断入口唯一** = `wiki_log.py truncate`（`wiki_log_tidy.py truncate` 仅委托它）；索引生成逻辑归属 `tools/wiki_log_tidy.py index`。
- **三层载体**：`logs/log.md`（当轮明细）→ `logs/backup/`（跨轮归档）→ `logs/INDEX.md`（可路由索引）；⛔ 禁在 wiki 页里写死 `log_YYYY-MM-DD.md` 文件名（日期会变），⛔ 禁手工编辑 `logs/INDEX.md`。
- ⛔ log 之外任何页面不得承载「过程叙事」。

## 三、增长规则（防止 ADR / 教训无限膨胀）

### 3.1 ADR 新增流程（**先合并，后新建**）

```
收到新决策需求
  ├─ Step 1  检索 wiki/decisions/ 现有页（按主题关键词）
  │     ├─ 命中同类 ADR → 【合并路径】见 3.1.1
  │     └─ 未命中       → 【新建路径】见 3.1.2
```

**3.1.1 合并路径（首选）**：向既有 ADR 页**追加一节**，而不是新建页。

```markdown
## 演进记录

### 2026-10-30 · 决策 D5 · <一句话主题>
- **变更**：<改了什么，≤80 字符>
- **理由**：<为什么，≤80 字符>
- **影响**：<受影响页面/模块，≤80 字符>
```

规则：
- 追加节**必须**放在该 ADR 页 `## 相关页面` 之前。
- 追加节标题 = `### YYYY-MM-DD · 决策 D<N> · 主题`，`<N>` 为该页内递增编号。
- 每条演进记录 ≤3 行。
- **仅当**决策与既有页主题**实质不同**（不同子系统/不同层级决策）才允许新建页。

**3.1.2 新建路径（例外）**：满足以下全部条件方可新建：
1. `tools/adr_new.py check` 报告「无同主题候选」**且相似度判据无超阈值页对**；
2. 新页**必须**符合 §2.2 结构契约；
3. 新页**必须**在 [[decisions/ADR-Index]] 与 `wiki/index/index.md` 各登记一行（由脚本完成）。

> **相似度闸门（2026-11-17 治理轮新增，强制）**：`adr_new.py check` 的判据分两层 ——
> ① **关键词子串计数**（原实现，只能提示候选）；② **落地实体符号 Jaccard**
> （`Class.Member` / `Method()` / `ROOT/KEY` 形态，**≥0.40 即判疑似重复**）。
> `adr_new.py new` 会**强制**跑第②层，命中即**拒绝新建**（退出码 2）并要求走合并路径。
> ⛔ **判「是否重复」不得看标题或正文措辞** —— 同主题不同子问题的页对，正文 4-gram 相似度可高达 0.14
> （2026-11-17 全库审计实测：5671 页对中仅 1 对落地实体 Jaccard ≥0.40）；
> 落地实体符号是唯一能把「真重复」与「主题相邻」区分开的判据。

**3.1.3 合并路径（并入他页时，2026-11-17 治理轮新增）**：当新决策与既有 ADR **实质同主题**时，
除「在既有页追加演进记录」外，还须走**整页合并**：

1. 承接页 frontmatter 加 `merged_from: [ADR-0XX]`（记被并的**旧号**，⛔ 不写承接页自己的号）；
2. 承接页正文加「## 合并自 ADR-0XX · <原页标题>」小节，收原页的**决策 / 背景 / 后果**；
   ⛔ **剥离「## 验证 / ## 验收」段**（验证过程叙事属 log，见 §2.2 R2），以守住整合页 ≤300 行上限；
3. 原页**删除**；⛔ **不重排序号**（重排会改 3000+ 处引用）——
   旧号在 [[decisions/ADR-Index]] 保留**指针行**（`| 040 | → [[decisions/ADR-033-…]] | …（已并入 ADR-033，原页已删；编号不回收） | deprecated |`），
   编号区间因此保持连续无空洞；
4. 全库指向被并页的引用 —— 三类形态都要改：① `[[decisions/…]]` 双链；② 裸号 `ADR-0XX`；③ 相对路径的 Markdown 链接（`ADR-0XX-Slug.md` 作为链接目标）——
   **一律改指承接页**；⛔ 不得残留指向已删页的链接；
5. 承接页标题的「整合旧 XXX」标注与 `merged_from` 必须与指针行一致。

**编号规则**：新号 = `ADR-Index` 中 `max+1`（当前 = **108**）。⛔ 废止某 ADR **不回收编号**。

### 3.2 教训新增流程（**先合并，后新建**）

```
收到新坑
  ├─ Step 1 检索 wiki/lessons/ 现有页（同关键词/同子系统）
  │     ├─ 命中同族 → 【合并路径】向该页追加
  │     └─ 未命中   → 【新建路径】
```

**合并路径**：向既有教训页追加：

```markdown
## 追加条目

### 坑 <N+1> · <一句话标题>（YYYY-MM-DD）
- **现象**：<≤80 字符>
- **判据**：<≤80 字符>
- **预防**：<≤80 字符>
```

**新建路径**：新建页须符合 §2.3 结构契约，并同步 §五 表行与摘要计数（由 `tools/lesson_new.py` 完成）。

### 3.3 规则新增流程（**先合并，后新建**）

```
收到新规则需求
  ├─ Step 0 判归属（§2.4b 边界判据）
  │     ├─ 约束「工作流怎么做」      → 进 Step 1
  │     ├─ 约束「代码 / 知识库内容」  → ⛔ 不进 rules/，归 lessons/ 或 standards/
  │     └─ 决策「为什么这么定」      → ⛔ 不进 rules/，归 decisions/
  └─ Step 1 检索 wiki/rules/ 现有页（按主题关键词）
        ├─ 命中同主题 KR → 【合并路径】追加「## 演进记录」
        └─ 未命中         → 【新建路径】
```

- **合并路径**：`python tools/rules_new.py merge KR-NNN "主题" "变更" "理由" "影响"`
- **新建路径**：`python tools/rules_new.py check <关键词>` 确认无候选 → `python tools/rules_new.py new <slug> <标题> "一句话规则" "正文" "判据"`（自动分配新号 + 登记 Rules-Index）
- **⛔ 规则正文只在本类目维护**；⛔ Skill 只写「去哪查」（见 §六）。
- **⛔ 内容类规则不得新建 `rules/` 页** —— 它会让「查流程规则」退化为「查技术判据」。

### 3.4 数量上限（硬闸门）

| 类别 | 上限 | 超限处置 |
|---|---|---|
| ADR 页 | 120 页 | 强制合并（同主题页数 ≤3 页，否则拒绝登记） |
| lessons 页 | 40 页 | 同上 |

## 六、Skill 指向规则（防漂移）

> **原则**：**Skill 写「怎么查」，Wiki 写「查什么」。**
> Skill 里一旦写死具体页名（`ADR-008-xxx` / `lessons/yyy`），该页重编、拆分、合并后指向即失效 —— 且**失效后比没有更危险**（读者以为那是权威）。
> 实证：2026-10-30 治理轮把判据库拆成 7 页、相机教训拆成 5 页，Skill 中原写死的 40 处内容页引用瞬间失效。

### 6.1 允许的两种指向

| 类型 | 允许内容 | 例子 |
|---|---|---|
| **角色级锚点** | 目录/索引/规范页（长期稳定） | `wiki/index/index.md` · `wiki/decisions/ADR-Index.md` · `wiki/architecture/CodeMap.md` · `wiki/project/vibecoding-workflow.md` · `wiki/standards/WikiPageFormatSpec.md` · `wiki/guides/ExecutionEnvironment.md` · `wiki/guides/RawAssetCatalog.md` |
| **机制表述** | 「去哪查」而非「查哪一页」 | 「读 index 第五节定位教训页」→「先查代码地图再 Grep」→「经 ADR-Index 按主题定位 ADR」 |

### 6.2 禁止的四种写法

| 禁止 | 反例 | 正解 |
|---|---|---|
| 写死具体 ADR 号 | `ADR-008-UIFrameworkMigration` | 「按 index 路由表定位该场景的 ADR」 |
| 写死具体教训页 | `lessons/CSharp-Language-Pitfalls.md` | 「读 index 第五节找相关教训页」 |
| 维护内容清单表 | 表格列出 20 条 ADR 约束 | 「约束由 ADR 页的『决策/后果』承载，现查」 |
| 抄判据正文进 Skill | 把 17 KB 判据搬进 Step | 「判据库在 lessons 下，按主题拆分页定位」 |

### 6.3 机械闸门

`tools/skill_pointer_check.py` 检查仓库版与用户级两份 SKILL：
- **C1** 无写死内容页（只允许 §6.1 的角色级锚点）
- **C2** 无红链
- **C3** 引用的 tools 脚本存在
- **C4** 引用的 ADR 号在现行 ADR 页中存在
- **C5** 无连续 ≥3 行的内容清单表

⛔ Phase 4 必跑，违规非零退出。

### 6.4 通用纪律（可写死的部分）

**技术契约**（编译期/语言期事实，不随页重组而变）可以写在 Skill 里：C# 7.3 语法边界 · `DisposeComponents()` 禁用 `Dispose(bool)` · `InitializeComponent()` 禁循环/条件 · 禁 code-graph · 配置须经 `WeldParamManager` · 新建 .cs 须注册 .csproj。

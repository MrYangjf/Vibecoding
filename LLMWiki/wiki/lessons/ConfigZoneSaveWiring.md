# 配置分区落盘接线：三类「界面无感」缺陷

> 2026-10-23 三界面（系统设置 / 工艺设置 / 通讯调试）参数与按钮一致性盘查产出。
> 与 [[lessons/SignatureAndWiringConsistency]] 的「接线完整性」是**同一族**：
> 那页讲「方法加了没人调」，本页讲「**配置能读能写、按钮也点了，但值没落到该落的地方**」。
> 决策与修法见 [[decisions/ADR-076-SettingsZoneSaveWiring]]。

## 一、三类缺陷的共同特征：界面全是绿的

| 缺陷 | 界面表现 | 为什么全绿 |
|---|---|---|
| **赋值晚于落盘** | 点「保存」弹「已保存」，重启回旧值 | 赋值写在内存里（运行时正确），只是**晚于**落盘调用 ⇒ 本次不落文件；**运行期看不出问题，重启才暴露** |
| **落到了别人的区** | 同上 | 分区落盘接口**只写本区键**，写错区 = 静默无操作（无异常、无日志） |
| **跨区副作用** | 在 A 页「修改」（不落盘）→ 去 B 页「保存」→ A 页的参数也被写盘 | 落盘接口写的是**内存当前值**，不区分「本按钮写的」与「别处改的」 |

⛔ **共同教训**：这三条**都不产生异常、不产生日志、不产生编译错误** ⇒ 静态校验若只看「键在不在」「调用点有没有」，必然全绿。

## 二、判据清单（编码前后各跑一次）

### 判据 A：每个配置项的「UI 落点 ↔ 落盘分区」必须一致

1. 列出该配置项的**唯一 UI 落点**（在哪个页、哪个控件）；
2. 查其**文件承载**（XML 路径 / INI 段+键）与**所在分区方法**（`Load/SaveZoneXml|Xml` / `Load/SaveZoneIni`）；
3. 断言：**UI 落点页的分区 == 该项被读写的分区**，且**该项只被一个分区方法读写**（两区同写 = 归属漂移）。

> 反例（2026-10-23 实测）：`MaxMapPoints` 的 UI 已迁系统设置页「线激光点过滤」区，落盘却仍写 ④Preset 区，而系统设置页的「保存参数」只落 ①System 区 ⇒ **改了点了保存，重启回旧值**。

### 判据 B：保存按钮的落盘调用必须「晚于」全部赋值

对每个保存按钮，把方法体切成三段：**采集/Apply → 落盘/Save → 落盘后语句**，断言：

- 该按钮写入的**每一个配置项**，其赋值语句的位置 **<** 落盘调用位置；
- 落盘调用的分区 == 被写配置项的分区；
- **不出现**「本按钮根本没写的分区」的落盘调用（跨区副作用）；
- **不出现**全量保存接口（`SaveAlgorithmsConfig()`）用于单分区配置项。

> 反例：`BtnSaveAutoParam_Click` 里 `SaveAlgorithmsZone(Adapt)` 出现在 ⑤三项赋值**之前** ⇒ 三项本次不落盘。

### 判据 C：读取按钮必须走「文件重载入口」

对每个「读取」按钮，列出它回填的每个配置对象，断言**先调该对象的文件重载入口**再回填：

| 配置对象 | 文件重载入口 | 漏调后果 |
|---|---|---|
| `WeldAlgorithmsConfig` | `LoadAlgorithmsConfig()` | — |
| `WeldHeadConfig` | `MontionManager.LoadWeldHeadConfig()` | 「读取」读到内存旧值（该入口此前 **0 调用方**） |
| `LineLaserConfig` | `LineLaserManager.LoadConfig()` | — |

### 判据 D：同一批配置项只允许一条「UI→内存」入口

多个按钮（修改 / 保存 / 即改即存）若写同一批配置项，必须收敛到**同一个 `Apply*` 底座**，
且各按钮只负责「是否落盘 + 落哪个区」。反之：两处各写一遍 ⇒ 迟早一处的落盘分区写错（= 判据 B 的成因）。

## 三、静态校验写法上的三个坑（本轮实测）

| 坑 | 现象 | 正解 |
|---|---|---|
| **判据太窄** | 「方法体内含 `InvariantCulture`」判负向判据失败——实现把口径**委托**给 `TryReadDouble` 了 | 判据接受「自带解析 **或** 委托给已含该口径的方法」；**负向判据要取反**（缺陷存在 = 判据失败） |
| **禁词表混入近似合法词** | 把 `value` 当保留字 ⇒ 存量合法代码全报 FAIL | 只拦**真保留字**（`params`/`base`/`this`/`default`/`lock`/`operator`/`event`/`delegate`/`out`/`ref`/`in`/`is`/`as`）；`value`/`record`/`group`/`where`/`select` 在 C# 中**合法**（见 [[lessons/CSharp-Language-Pitfalls]] 近似关键字清单） |
| **控件引用闭环误捕方法名与字符串** | `btnXxx_Click`、`"radioQuickLaGalvo"` 被当成「未声明的控件」 | 差集 = 控件标识符 − Designer 字段声明 − **本文件定义的方法名** − **字符串字面量内的词元** |

> ⚠️ **失败集与成功集按形态二分 ⇒ 先自审判据，不要怀疑代码**（本轮 5 项 FAIL 全是判据形态问题，0 项代码缺陷）。

## 四、阴性对照必须做

判据写完先**注入旧行为**（把修好的代码改回缺陷写法），确认对应判据**确实 FAIL**：

- 注入「Adapt→System」「Preset→全量」「Quick→全量」「删 MAX_MAP_POINTS 写」「删 LoadWeldHeadConfig」5 组；
- 全部被抓到 ⇒ 判据有区分度；
- **注入必须自证命中**（按方法体定位替换，报告是否命中）——否则「判据没抓到」会被误读成「判据无区分度」。

## 五、附带发现（本轮同批记录，未改代码）

- **配置项被运行期链路覆盖 ⇒ 界面改了不生效**：`galvo.Width/Length`（振镜宽/长）与 `Frequency`（频率）在生产工作流里每拍被覆盖（写入摆幅 amplitude 与查表频率），界面输入项运行期无效但**能落盘** ⇒ 落盘值是死值。属「配置可读可写但无消费者」，需业主裁定语义（⚠️ 不属本 ADR 范围）。
- **调试面板与生产链路共用回复缓存**：通讯调试页「写入焊参通道」写入的值被生产工作流每拍覆盖，仅一周期可见 ⇒ 面板已补提示日志。

### 坑 1 · 读取入口只读内存快照（2026-11-04）
- **现象**：点读取参数界面数值不变；awcfg 导入后提示回读成功但工艺参数未生效
- **判据**：读写器仅构造期读盘，LoadAlgorithmsConfig 未 Reload 就按缓存解析
- **预防**：读取入口先 Reload 磁盘再解析；XdocumentReaderWriter 补 Reload()

### 坑 2 · 组合加载入口漏分组 / 整型参数被截断 / 写目标缺失静默放行（2026-11-04）
- **现象**：① 进工艺设置页 TA 区（下压力 / Pose1 / Pose2 / Break）全空，必须先点「读取参数」；
  ② 系统设置页「扭矩爬升速率」填小数后点「修改」再「读取」仍显示 0，且没有任何提示（该入口 2026-11-05 已迁至 TA 轴「参数」弹窗，缺陷类型仍是同一教训）。
- **判据**：
  - 组合加载入口（`LoadAlgoConfigOnForm` 这类）只调了部分分区加载器，**漏一个区** ⇒ 该区构造期与页面显示全是默认值，按钮一读才出现；
  - 配置项在驱动器侧是 U16，UI 却用 `double` 校验后 `(uint)` 强转 ⇒ 小数被**静默截断**为 0，配置里也存 0；
  - 写入前 `if (target != null)` 静默跳过且照常返回成功 ⇒ 值没写进去、界面却显示「已应用」。
- **预防**：① 组合加载入口必须逐个分区加载器列全，新增分区同时加进入口与「首开补载」守卫；
  ② 整型驱动器参数改用整数解析 + 范围校验（`TryReadInt`），越界/小数必须**弹窗**而非只写日志；
  ③ 写入前先定位目标对象，定位失败立即返回失败；成功后回填**内存真实值**并给可见回执。

### 坑 3 · 有符号参数被界面校验抹成「只能填正数」/ 小数被 `(short)` 静默截成 0（2026-11-04）
- **现象**：① TA 下压力填 `-50` 保存被拒（弹「请输入有效的下压力(N)」），现场无法设置反向出力；
  ② 填 `-0.5`（或 `0.5`）能保存、也能回填，但点指令后**不出力且无任何提示**。
- **判据**：
  - 业务语义已确认「负号 = 反向出力」时，界面校验里出现 `force < 0` / `Math.Abs` 一律判非法 ⇒ **符号被 UI 抹掉**，与底层对称区间（`SetTorque` ±1000）口径错位；
  - UI 用 `double` 校验、下游用 `(short)` / `(uint)` 强转 ⇒ 向零取整后得 0；而底层对 `0` 是**判参数非法并拒绝**（`Target_Torque` 千分比 1~1000）⇒ 「保存成功 = 不出力」的静默失败。
- **预防**：① 有符号量按业务口径给**对称区间**，并在提示文案写明「负值=反向、0 非法」；
  ② 界面层按下游强转规则（`(short)`/`(uint)`）先算一遍，结果为 0 就**当场拦下**并提示「绝对值需 ≥1」，不放行到指令层；
  ③ 回填保留符号（`F1` 格式），⛔ 不做 `Math.Abs` 归一。
  关联 [[decisions/ADR-080-DeltaTorqueHomingSignedModeAndDetectParams]] 决策 D4 · [[api/ProcessControlPage]]。

### 坑 4 · 初始化完成不等于轴已使能（全局缺口，无任何主动使能点，2026-11-04）
- **现象**：启动完成、初始化结束、界面已放开操作，但 TA 轴驱动器仍非 OperationEnabled；只有点 `TA_Auto` 才在内部补一次 `ServoOn` 才发现；Y 轴等同样如此。
- **判据**：
  - 全项目检索 `ServoOnAll()` **0 调用方**、初始化链路（`MontionManager.Initialization()` / `DoResetMachine()` / `CascadeResetProcess()`）内**无** `ServoOn` ⇒ 使能只发生在「指令入口/手动按钮」，属全局缺口而非单轴差异；
  - 现象具有强迷惑性：界面 Enabled、日志无报错、单点指令时又「自己好了」。
- **预防**：① 初始化聚合判定通过后**统一使能一次**并逐轴留痕（轴名 + 结果 + 失败原因），失败即判初始化未完成；
  ② ⛔ 不用定时轮询重新使能掩盖急停/报警/总线未 OP；
  ③ 指令入口的临时 `ServoOn` 只作兜底，⛔ 不得成为唯一入口。
  关联 [[decisions/ADR-081-InitUniformServoOn]] · [[api/MontionManager]] · [[api/DeviceControlWork]]。

### 坑 5 · 同一参数两套通路：专用 P 群组报「参数不存在」、SDO 才有对象（2026-11-04）
- **现象**：写 P1.087/P1.088 一直返回 `5376`（0x1500，「此驅動器參數不存在」），但 ASDA Soft 里这两个参数明明存在、可改。
- **判据**：
  - `5376` 是 **P 群组服务自己**的返回码（手册 §33.5 印刷 33-5 / PDF p.942，详表 33-24 / PDF p.961），只说明「这条通路查不到该参数」，
    **不等于**驱动器没有该参数 ⇒ 不要据此判「驱动器不支持」；
  - 参数实际上在对象字典里（P1-xxx = `16#2100 + xxx`，P1.087→`16#2157`、P1.088→`16#2158`），SDO 通路（手册 §7-2，PDF p.162
    「使用 SDO才可以讀寫到 PDO組成表單以外的任一組 OD碼」）才是它的正规读写入口；
  - DLL 导出表里没有 `*_COE_Home*` 之类的命名 ⇒ 厂商截图里的 `WriteParameter_CoE_Home*` 是 **PLC 侧 FB**，不是本 DLL 接口。
- **预防**：① 换通路前先查**对象字典**（ESI / 厂商映射表）确认对象是否存在，再定接口；② 两条通路的错误码体系不同
  （P 群组返回码 vs SDO abort code），日志必须各自释义，⛔ 不能只打数字；③ `0x06020000`（对象不存在）才是「驱动器不支持」
  的证据，出现即锁定不硬写并明确给降级方向，⛔ 不静默吞掉；④ `ParaType=2`（Servo ON 不可设定）的参数写入点必须排在
  `Set_Svon(1)` 之前，回零前重复下发走「先读后写」。
  关联 [[decisions/ADR-080-DeltaTorqueHomingSignedModeAndDetectParams]] 决策 D5 · [[guides/DeltaEtherCAT-DevGuide]]。

### 坑 6 · 「工作零位」被写成「回零」：绝对编码器轴上白跑 Home_Move 且污染 6098 链路（2026-11-05）
- **现象**：TA 初始化要求「使能后走到工作零位」，实现时容易直接复用 `Home()`（`Home_Config` 6098/6099/609A + `Home_Move`），
  日志也写「回零」，现场无法区分是工作零位定位还是原点校准。
- **事实**：TA 轴为**绝对编码器、掉电保留位置**，正常生产不需要回零；工作零位只是「按绝对坐标走一次 CSP 点位」。
  两者混用会带来三个后果：① 每次初始化都跑一次回零（慢且可能撞硬限位）；② 6098/6099/609A 被意外改写，破坏现场回零参数；
  ③ 若把 `Home_Status` 当作到位门禁，绝对位置明明有效却被「回零中/回零错误」卡死。
- **判据**：
  - `TA_ZeroPose` 只允许 `CSP_Start_Move`（posMode=1 绝对）或等价 `AbsMoveNoBlock`，到位判定用 `|当前位置 - 目标坐标| ≤ 容差`；
  - ⛔ 初始化链内不得出现 `Home_Config` / `Home_Move` 调用；`Home_Status` 只用于回零流程（`StartHome`/`WaitHomeDone`）；
  - 日志前缀必须自带区分（「TA_ZeroPose（工作零位，绝对编码器定位 ≠ 回零）」），状态位也不得与回零共用。
- **预防**：新增/修改轴动作前先问「这是位置指令还是原点校准」；配置键放 `ROOT/TA_HOME` 的 `TA_HOME_ZERO_POSE_*`
  （目标/速度/容差），⛔ 不要复用 `HomeOffset`（那是回零偏移，单位与语义都不同）。
  关联 [[decisions/ADR-082-TaInitFourStepAndAvailability]] · [[api/MontionManager]]。

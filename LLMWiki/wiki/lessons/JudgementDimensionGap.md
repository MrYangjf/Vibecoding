# 判据维度缺失：查「存在性」不等于查「唯一性」

## 现象

2026-10-21 RSI 数值化改造交付后，业主编译报：**类型 `KukaRsiComm` 已经包含 `TxPacketCount` 的定义**等等很多重复定义。

实测：公开属性块被插入了 **10 份**（`RxPacketCount` / `TxPacketCount` / `LastRxRaw` /
`LastTxRaw` / `LastRxCmd` / `LastRxPayload` / `LastIpoc` 各 10 份）。

## 为什么静态校验 47/47 全绿

⛔ **判据只查「存在性」，不查「唯一性」**：

```python
missing_ph = [p for p in placeholders if ('"%s"' % p) not in rsi]
check('J9 占位符体系完整', len(missing_ph) == 0)
```

「10 个占位符都在」⇒ PASS。**重复 10 份也照样 PASS**。

> ⭐ **这不是「正则空过」（判据抓不到），而是「判据维度缺失」（判据只覆盖了一半的问题面）**。
> 判据能问「在不在」，但没问「是不是只有一份」。

## 根因链（三层）

1. **重放脚本幂等性失效**：`rep()` 判「已应用」用 `a in s`（锚点存在）。
   而插入型补丁的锚点 `a` **包含在结果 `b` 里** ⇒ 第二次运行再插一遍。
2. **重复执行**：我在同一轮里跑了 3 次重放脚本（恢复 1 次 + 验证幂等 2 次）⇒ 3 次插入。
3. **判据无唯一性维度** ⇒ 47/47 全绿放行，直到业主编译才暴露。

## 正解

### ① 判据补「唯一性」维度（本轮新增 J37 / J38）

- **J37 通用**：按 class 切块 → 同类内「同名 + 同参数类型签名」的成员出现 >1 次 ⇒ FAIL。
  - ⛔ 三个误报坑（写判据时踩过）：① 局部变量被当成员（须**行首**修饰符）
    ② 跨类同名合法（两个类的 `Name`）⇒ 须**按 class 切块**且**排除嵌套类体**
    ③ 重载方法合法（`Initialize(string)` vs `Initialize(RSIConfig)`）⇒ 键用**参数类型列表**而非个数
- **J38 显式清单**：本轮新增的 10 个公开成员逐个断言「唯一定义」⇒ 兜底通用正则的漏网。

### ② 重放脚本幂等三态（`rep()` 的正确判定顺序）

```
① b 唯一（≥20 字符且全文出现 1 次）且 b 在 s 中  → 已应用，跳过
② a 不在 s 中                                   → 目标已消失，视为已完成，跳过
③ b 不唯一（太短/多次出现）但 a 在 s 中           → 必须应用（否则漏删）
④ 其余                                           → 锚点未命中，报告
```

⚠️ `b` 太短（如 `        #endregion`）**不具唯一性** ⇒ 不能用它判「已应用」，
否则「删 EKI handler」这类补丁会被误判为已做而**漏删**（本轮实际发生）。

### ③ 幂等必须**实测**，不能靠推理

判据「脚本是幂等的」这句话本身不可信 ⇒ 必须跑：
`md5 清单 → 执行 → md5 清单 → diff`（本轮口径：**9 文件 × 3 次执行零变化**）。

## 可推广的判据

> ⭐ **凡「某东西应该只有一份」的场合（成员定义、文件登记、配置键、事件订阅），
> 判据必须查「计数 == 1」，不能只查「存在」。**
>
> ⛔ **重放/补丁脚本的幂等性，判据是「锚点是否被消耗」**：
> 插入型补丁的锚点**必须**被替换掉，或用**特征串 marker** 判重
> （marker 必须是「本步的产出」，⛔ 不能是「待删内容」——否则第一步自我跳过）。
>
> ⭐ **写完补丁脚本必须做三重自证**：
> ① 干净基线 → 执行 → 结果正确；② 再执行 → 文件零变化（md5 diff）；
> ③ 故意注入该类错误 → 判据必须 FAIL（阳性对照）。

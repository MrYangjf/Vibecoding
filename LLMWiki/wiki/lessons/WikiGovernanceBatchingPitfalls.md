# 批量治理与脚本化改写的事故清单

> **一句话**：本轮全库治理（ADR 编号重编 + index 瘦身 + 格式规范化 + 大页拆分）中途发生 **6 次工具事故**，全部源于「脚本假设 ≠ 磁盘实况」，本清单逐条记录坑与判据。

## 现象

| # | 现象 | 根因 | 判据 / 正解 |
|---|---|---|---|
| 1 | 27 个 ADR 文件「消失」 | 重命名分两段（先 `__TMP__068.md` 再改新名），第二段因 `slugs[n]` 键类型错（int vs str）**中途异常退出**，文件停在临时名 | 改名**必须一次到位**；或用「先全部收集 → 校验键齐全 → 再统一改名」。**任何改名后必须 `Get-ChildItem` 核对文件数与文件名** |
| 2 | 文件名变成 `ADR-052-ProductionRecordSchema`（**丢 `.md`**） | 新名由 slug 拼接，忘记补扩展名 | 改名后断言 `name.endswith('.md')`；**目录清单前后对比** |
| 3 | 27 个 ADR 文件的内容编号与文件名**错位**（标题写 052、文件名 068） | 「改名」与「内容重编」分两步，第二步的映射表用新号反查旧号，方向搞反 | **单向映射**：`旧号 → 新号` 只建一次；⛔ 禁止用新号反推旧号 |
| 4 | 页面**双层链接** `[[decisions/X]]` + 尾部缺 `]]` | 替换链接正则的 alias 分组写错，`(?:\|[^\]]*)?` 吞掉了 alias 但没补回 | 链接正则改写后**必须做括号配平断言**（`[[` 与 `]]` 计数相等），断言不过则不写盘 |
| 5 | 速查路由表**链接被截断**（`[[decisions/ADR-042-...` 无闭合） | 超长文本按字符数硬截断，切断了 `[[...]]` | 截断的**最小单位必须是完整链接单元**，不得切断链接；截断后仍须做括号配平断言 |
| 6 | 教训页尾部出现**空的 `## 现象/## 根因/## 判据/## 预防`** | 规范化脚本给存量多坑页补骨架时，把「多坑页的 `### 现象`」误判为「缺章节」 | 补骨架前先判「页内是否已有同名 `### ` 子章节」；有则**跳过**，不得追加尾部空壳 |

## 根因

**「批量脚本」与「逐文件审查」的边界没划清**：凡是需要**语义判断**的（哪个旧号对应哪个现行页、哪些章节可删），脚本只能**列出候选**，必须由人逐条确认；脚本只负责**机械可判定**的（改号、改名、搬文件、算行数）。

另一条根因：**BOM 与行尾**。
- 带 BOM 的文件首行是 `\ufeff---`，`lines[0].strip() == "---"` 判空**失败** ⇒ frontmatter 解析整段跳过 ⇒ 规范化「看起来跑了」但字段没补（现象 7）。
- 写回时若把 BOM 位置搞错，会产生 `---` 前多一个不可见字符。

## 判据

- **改名类脚本**：收集 → 键完整性自检 → 一次改完 → 目录清单前后对比（文件数、扩展名、编号区间）。
- **编号重编类脚本**：**单向映射表**，只建 `旧→新`；⛔ 禁止反查。
- **任何文本改写**：写盘前断言「`[[`/`]]` 计数不变」「行数变化符合预期」；断言不过 ⇒ **中止且不写盘**。
- **任何批量改写**：先在**备份**上跑一遍并 diff，确认无误再对工作树执行（脚本崩溃是常态，不是例外）。
- **BOM 文件**：判 frontmatter 前先剥 `\ufeff`；写回时 BOM 位置不变。
- **行尾**：按字节读写，保持 BOM / CRLF / LF 同质；禁止 `open(p).read()` + `open(p,"w").write()`。

## 预防

- ⛔ **禁止**在未备份的工作树上跑「会改名的脚本」——本轮因此需要从 `LLMWiki_backup_20261030_133312.tar.gz` 回滚重来一次。
- ⛔ **禁止**用「脚本输出的统计」当验收——统计会骗人（现象 6 的规范化脚本报告「97 文件已写盘」，实际字段没补）。
- ✅ 每个批量脚本必须**自带断言**（括号配平 / 文件名格式 / 键完整性），断言失败即中止。
- ✅ 涉及语义的映射（旧号→现行页）**逐条人工裁定并留档**，脚本只消费裁定结果，不自行推断。
- ✅ 改完立刻跑**六扫描器**（含新增的 `wiki_format.py`）——本轮正是靠 `wiki_format.py` 抓出了「frontmatter 未补」与「双层链接」。

## 退役旧指引的三档处理

> **规则要点（原 rules/KR-015）**：新架构页取代旧内容时**禁止一刀切批量删改**，先分档再处置。

| 档 | 适用 | 处置 |
|---|---|---|
| 整页废弃 | 结论已被完全取代 | frontmatter 置 `status: deprecated` + ⛔ 横幅（列「旧机制 → 处置 → 现行做法」），**正文保留作历史** |
| 仅术语过时 | 结论仍成立，只是载体改名 / 移除 | 只加沿革横幅，**保留结论** |
| 经验存活 | 教训页的坑可越过产生它的机制继续存活 | **逐条**判 ✅ 保留 / ⚠️ 折中 / ⛔ 失效，只把机制专属部分标 ⛔ |

- **子档 · 单条 ADR 条款被取代**：⛔ 不得把整页降级为 `deprecated` —— 用「删除线 + ⛔ 已被 ADR-NNN 演进/废止」就地标注，该 ADR 保持 `accepted`；**条款号是稳定交叉引用，不得重编号**。
- **判据**：处置后必须全库扫旧机制的特征符号，确保每个命中都落在删除线内或带「已删除 / 已失效」字样；`[[链接]]` 统一改写为「删除线旧名 → 新权威页」，读者不得跟到死标准。

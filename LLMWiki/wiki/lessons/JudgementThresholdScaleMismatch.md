# 判据阈值与信号尺度失配

> 来源：2026-09-22 焊缝跟踪 CSP 输出整形连续两轮迭代（[[decisions/ADR-042-SeamTrackingConsolidated|ADR-042（焊缝跟踪综合）]] → [[decisions/ADR-042-SeamTrackingConsolidated|ADR-042（焊缝跟踪综合）]]）。
> 四类坑的共同特征：**代码「逻辑对」，但判据量与被判据量的尺度不匹配，或在错误的坐标系里取残差**，于是判据恒真/恒假、修正永不生效，且编译器与扫描器全绿。

---

## 坑一：整形/限幅器的残差取错了参照系 ⇒ 数学上自锁

**现象**：为「防过冲」加一条按剩余距离限速的整形器后，命令**完全不推进**（85.5% 的采样点段距恰为 0），写段占空比从 41.7% 崩到 7.3%。

**错误写法**：

```csharp
double smoothedTarget = current + smoothedVelocity * tickSeconds;  // 已含本拍行程
double remaining = Math.Abs(target - smoothedTarget);              // ⇒ 加速度限幅不生效时恒为 0
double brakeVelocity = Math.Sqrt(2.0 * MaxAcc * remaining);        // ⇒ 0
if (Math.Abs(smoothedVelocity) > brakeVelocity) { /* 速度被清零 */ }
```

**根因**：`remaining` 的被减数里已经包含了本拍要走的 `v·dt`。当加速度限幅不生效（常态）时 `v·dt ≡ target − current`，于是 `remaining ≡ 0` ⇒ `brakeVelocity = 0` ⇒ 速度被清零 ⇒ 输出恒等于 `current`。**只有绕过限幅器的分支才动**，整形链整体失效。

**判据 / 规避**：
- 限幅类整形器的残差**必须取自「当前位置 → 目标」**，即 `error = target - current`；`√(2·a·e)` 才是经典制动曲线。
- 自检问法：**「若本拍输出恰好等于目标，这条判据会不会把速度清零？」** 会，则参照系取错。
- 更一般的自检：把判据代入「输出 = 目标」这个稳态解，若判据把系统推回非稳态，即为自锁。

## 坑二：「静止/推进」类判据的阈值小于每拍信号变化 ⇒ 判据恒真

**现象**：为防止「把浮点抖动当成目标推进」，把推进阈值取为单脉冲当量（1μm）。实测每拍目标位移约 0.9~1μm ⇒ 计数器几乎每拍 +1 ⇒「目标已连续静止」**恒为真**，「连续静止 5 拍才允许贴齐」的门控形同虚设，贴齐在 89.1% 的采样点触发。

**判据 / 规避**：
- 任何「判定信号是否在变化」的阈值，必须**明显小于**该信号在**最快工况**下的每拍变化量，或改用**时间窗**判据（如「在 N 拍窗口内位移 < x」）而非逐拍差分阈值。
- 落地前用一个数值问句验收：**「本阈值 ÷ 每拍典型位移 = ?」** 若结果 ≤ 1~2，判据必然恒真。
- 阈值应当与**上游采样率/信号速率**一起标定，而不是只按物理量纲选一个「看起来很小」的值。

## 坑三：配置默认值 ≠ 生效值（INI 无条件写全键）

**现象**：把 `CspMinSegMm` 的**代码默认值**从 0.005 改成 0.001，现场门限**纹丝不动**仍为 5μm。证据：被拒段距 0.0011~0.0039、放行段距 ≥0.0070，分界清晰。

**根因**：`SaveProcessIni` **无条件写全部键**。只要现场曾点过一次「保存」，INI 就固化了当时界面上的值；此后改代码默认值永远不生效。同一陷阱在 `OutputDeadbandMm` 上重复出现。

**判据 / 规避**：
- 改「默认值」时要先问：**这个键的写入侧是否无条件全量写？存量 INI 里是否已有该键？** 若已有，改默认值 = 无效改动。
- 修复方式二选一：① 在**加载期**加护栏钳位（`if (x > 上界) x = 上界;`，与既有 `if (x <= 0) x = 默认;` 同风格）；② 取消该配置项在关键判据上的参与（硬编为物理下限）。
- 收口动作：在**起焊首条日志**整行打印全部生效配置（跟随时间常数 / 写段门限 / 输出死区 / 耗干阈值），使「改动是否生效」变成读一行日志即可判定。
- 与 [[guides/Namespace-Compilation]] 的「配置项四点闭环」互补：四点闭环保证**链不空**，本坑保证**链上取到的值是新的**。

## 坑四：门限/死区与信号量子同量级 ⇒ 节拍被切碎

**现象**（承 ADR-042）：写段门限 5μm 与每拍命令步长 4.8μm 同量级 ⇒ 56% 的拍写不出段、驱动器约 44% 占空比。**同类**：算法侧输出死区 50μm，而轴速仅 92μm/s ⇒ 目标「保持 543ms 后跳 50μm」，下游任何跟随器都只能复现台阶。

**判据 / 规避**：
- 任何「小于它就不动作」的门限，必须**远小于**（建议 ≤ 1/5）该信号在**最慢工况**下的单拍变化量，或明确接受「按门限量化」的代价。
- 门限的**立论对象**必须与**判据量**一致：本项目 `CspMinSegMm` 的立论是「伺服反馈噪声」，而判据量是**命令**——命令侧噪声早已由滤波器与方向锁处理，属判据来源错配。
- 门限应取**物理可表示量**而非经验噪声带：脉冲域判据的真下限是「1 个脉冲」（`ToPulse` 截断取整）。另见 [[lessons/AlgorithmControlRecordIsolation]] 的职责隔离口径。

## 坑五：观测口径必须与采样口径一致，否则会把采样假象当机理

**现象**：轨迹记录按 `robotX` 去重，而 `robotX` 由模拟时钟以约 21ms 刷新、输出节拍为 10ms ⇒ 记录行数仅 **47.7 行/s**，而 `缓冲诊断` 实测 **94.8 拍/s**。回看曲线的「点距不均/台阶」一半来自这个采样假象，会把人引向错误的机理假设。

**判据 / 规避**：
- 诊断结论落地前先问：**这份记录的采样口径与我要论证的节拍是否同频？** 若否，先看有没有更高频的计数器（本项目用「写段占空比 = 写段数/拍数」自带计数器，不受记录去重影响）。
- 记录侧要去重时，必须同时提供**未去重的计数器**作为交叉核对。
- 相关：[[lessons/SimulationAutoBranching]] 的「先排除工况前提（如无直线轴的正反馈漂移）再谈控制器」同源。

# TA 力矩冷启动不走斜坡与位置转力矩先反跑

> **一句话**：力矩目标不能在输出关闭时下发，位置残留与反向扭矩会先于新目标生效，必须停稳、同号种子、开输出后再下发目标。

## 现象

Break/Pose/Zero → TA_Auto 时力矩瞬间到位，改 `TORQUE_SLOPE` 无效；Auto↔Retract 却能看到爬升。Retract → Zero → Auto 每次 Auto 先反向动一下再回正。

## 根因

旧 `SetTorque` 先 `CST_Start_Move` 再 `CST_Output_Enable`：输出关闭期间目标已写入，开输出即到目标值，冷启动根本不经历斜坡；同时存在「输出态 ∧ 模式字 ∧ 参数未变」复用捷径可跳过下发。切 CST 前不停位置运动、也不清驱动器内上一次反向扭矩指令，位置残留与旧力矩符号被新动作继承。

## 判据

冷启动 = 位置停稳 → 切 CST → ±1‰ 方向种子 → 开输出 → 再下发目标 + slope；热切换 = 直接重发目标 + slope；⛔ 不设参数相同的跳过捷径；输出关闭期间「已爬完」的斜坡无法补救，必须输出开启后重发目标。

## 预防

- 所有进入力矩出力的路径都必须重新下发目标与 slope；在输出开启后下发目标；切 CST 前 `IsMoving` 停稳（3s 超时拒绝）并用与目标同号的 1‰ 方向种子覆盖残留；`WaitTaTorqueOn` 只判输出位/模式/故障/使能，不能当作「斜坡已生效」的证据。

## 追加条目

### 2026-11-06 符号翻转穿越零点 = 4s 才动 / 先反跑

- **现象**：Auto→Retract 要 4s 才动；Retract→Zero→Auto 每次先反跑再回来。
- **算术**：`TORQUE_SLOPE` 数值即 ‰/s。+270‰ ↔ −270‰ 的 `|Δ|=540‰`，`slope=200` 时 `540/200=2.7s`，加停稳与确认窗 ≈ 现场 4s；冷启动 ±1‰ 种子到目标 `270/200=1.35s`，全程符号为旧方向的指令仍在出力。
- **判据（⛔ 已被 2026-11-06 ADR-088 取代）**：本条曾主张「符号翻转改用更大的第二条斜率」。该做法已由业主收口**全部删除**，正反向只剩 `TORQUE_SLOPE` 一条。删除**不解决**跑飞与撞击——根因是 CST 只约束出力、不约束速度（见 [[decisions/ADR-088-TaSharedTorqueLimit]]）。
- **预防**：⛔ 不要用「撤力重建」解决反跑 —— 无出力窗口在弹簧/丝材反力下会加速回退，反而更糟；也不要为反转临时抬高上限（上限是 CSP 阻抗与保压的安全值）。若日志已出现「CST 进入前 位置运动已停稳」仍反跑，即残速假设被证伪，不要再往位置残留方向查。

### 2026-11-06 `0x1305` 被误标成 SDO 中止码

- **现象**：日志写「回读失败（读被中止，SDO 中止码 0x00001305）」，于是得出「本机型未实现 16#6072」。
- **判据**：标准 SDO abort 在 `0x0500~0x06FF`，`0x1305`（=4869）是**台达 DLL 自身返回码**，本地 `EtherCAT_DLL_Err.cs` 只收录到 `0x1304 = MAILBOX / SDO_BUFFER_FULL / ESC_FAILED`，`0x1305` 未收录。它与写 P1.087/P1.088 失败同码，说明**请求很可能没发出**（邮箱/上一笔未结束），而不是驱动器拒绝该对象。
- **预防**：①日志与文档必须分列「API 返回码」与「SDO 中止码」，⛔ 不得把 API 返回码写成「SDO 中止码」；②判定「对象未实现」前必须先做基线读（`16#6041` 状态字），基线失败时禁止下结论；③台达 P 参数 CoE 通道 `0x210C` 的 `SubIndex` 是**1 基轴号**（`_slotNo + 1`），按 0 读会读到别的对象（本次读到 65186/0xFEA2 即此因）。

### 2026-11-06 「更快」不等于「更平顺」：反向斜率不能一档到底 ⛔ 结论已废弃

> ⛔ **本节结论已被 [[decisions/ADR-088-TaSharedTorqueLimit]] 推翻，不得据此改码。**
> 根因不是「一条斜率管了两件事」，而是 **CST 只约束出力、不约束速度**：力持续作用时轴可一路加速到 439mm/s
> （定位速度仅 10mm/s），撞机械限位后反弹再撞另一头。拆斜率 / 改交接点 / 加守卫都**只在改变力建立快慢**，
> 治不了无限加速。正确方向是给轴加速度上限（路线查实见 ADR-088）。

- **现象**：反向斜率从 100（10%/s）提到 1000（100%/s），跑反窗口 2.7s → 0.27s，观感「一瞬间就回来了」，但换来「撞击、整机一颤」。
- **当时的推断（❌ 已被现场否证）**：单一斜率同时管了「穿越零点」和「把力建到满值」两件事，应拆成两段。
- **现场实测反证**：拆段后峰值速度仍达 **439.10 mm/s**，守卫触发时 271.88 mm/s —— 说明速度根本不是斜率决定的。
- **预防**：①看到「速度异常」先查该模式**有没有速度约束**，再谈斜率；②⛔ 不得在文档或对现场宣称「调斜率能治撞击」。

### 2026-11-06 同一类「写一个对象字典参数」不要造两套 SDO 时序

- **现象**：`16#6098`（回零模式）一直稳定成功，`16#6072`（扭矩上限）却接连报 `0x1305`；差别的不是对象，而是**函数**。
- **成因**：`16#6098` 走专用接口 `CS_ECAT_Slave_Home_Config`（握手在 DLL 内完成）；`16#6072` 却在轴类里自拼 `SDO_Quick_Send_Message` + 自己轮询 `SDO_Check_Done`，既无发起前等待，也不区分「请求未发出 / 请求发出后失败」。同一通道两套时序，出问题时无法与已知良好的那条对照。
- **判据**：对象字典写入属于**同一类操作**，必须共用同一个网关（本项目 = `DeltaSlaveDevice.ReadSdo/WriteSdo`）与同一套握手；只有 DLL 未暴露通用 Index 写入口时才用专用函数（如 `Home_Config` 一次写 6098/6099/609A），且不得反向再造一套通用 SDO。
- **预防**：①新增对象写入前先 Grep 现成网关调用方，⛔ 不在业务类里另写 `SDO_*` 轮询；②写窗口选在邮箱空闲时（`Set_MoveMode` 会占邮箱，SDO 应在其**之前**发），不靠加延时硬凑；③`SubIndex` 语义分两种，标准对象是**对象子索引**、台达 P 参数是**轴号**，⛔ 不得用同一形参混用。

### 2026-11-10 「同号种子」会在改参数前先送出一条反向指令

- **现象**：位置模式→力矩模式且本次方向与上次相反时，监控可见程序先发一次反向电流指令，随后才下发新目标。
- **成因**：冷启动的 ±1‰ 同号种子在输出开启前先写入目标；种子符号按新目标取，与驱动器内上次方向相反，故表现为一次反向预置。
- **判据**：位置模式电流已回到无方向值，切 CST 后不存在可继承的旧方向；此时种子不再是「覆盖残留」，而是额外的方向指令。
- **预防**：⛔ 冷启动不要在目标前插入任何方向指令；方向正确性由「停稳 → 切模式 → 目标 → 开输出」保证。若撤销后仍反跑，再按 ADR-087 的残速/穿零两条假设复验。

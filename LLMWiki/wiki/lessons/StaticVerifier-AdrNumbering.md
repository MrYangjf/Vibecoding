## 八、ADR 编号：本库有「两套编号空间」

⚠️ **实证碰撞**（2026-10-08）：P1 规划 ADR 052~058，而 `ADR-Index.md` 的**旧→新映射表**已占 052~067（每行标「并入 ADR-0XX」，**不是现行 ADR 但占着号**）。`lint_scan` 报「ADR 编号冲突 0」⇒ **该扫描器只查现行表，看不到旧段占位**。

| 编号段 | 性质 |
|---|---|
| **001~051** | 现行有效 ADR（有独立页面） |
| **052~067** | 旧编号段（映射表里，不可用） |
| **068~** | ⛔ **新增 ADR 从这里起** |

**新建 ADR 前必做**：grep `ADR-Index.md` 的**两张表**（只查现行表会漏）。同步计数要改**四处**：`ADR-Index` 头部 + 编号沿革 + 章节标题 + 表行；`index.md` 三处（分类摘要行 / 章节 `编号说明` / 7.0 编号总表）。

### 8.1 页内编号必须 == 文件名编号（2026-10-08 实证：24 页错位）

**现象**：`ADR-Index.md`（编号唯一准绳）与 `index.md`、文件名三者完全一致，但 **24 个 ADR 页的 `title:` / H1 自称编号停在上一代编号**（如 `ADR-009-…md` 的 H1 写 `ADR-027`）。后果：这些旧号与**其它现行页撞车**（`001`/`004`/`007` 各被 3 页占用）⇒ 按编号检索会命中多个不同决策。

**为什么三个扫描器都看不见**：`lint_scan` 的「ADR 编号冲突」只看**文件名**；`wiki_audit` 只看链接与 index 行；`drift_scan` 只看 `.cs` 名。**页内自称编号无人校验。**

**判据（三向 + 一个防复现）**：
```
① 对每个 ADR-NNN-*.md：title 首号 == H1 首号 == ADR-Index 行编号 == index.md 行编号 == NNN
   （取号正则要容忍：引号包裹 `"ADR-042：…"`、`旧` 前缀、`ADR-042：/ADR-042 —` 分隔符、
    H1 的 `# ` 前缀必须先剥掉；ADR-002 的 frontmatter 起始是 `--` 而非 `---` ⇒ 要能兜底找 title 行）
② 反向建「编号 → 占用页」图，任一编号被 >1 页占用即报错
③ 改文件名 / 重排编号的脚本，必须**同批回写**每页的 `title:` / H1 /（等于自指号的）`tags` token
```
⛔ **只改文件名 = 制造本类缺陷**（本库实测：工作树 49 个改名未回写，页内编号落后 ≥1 代）。

**tags 的判定边界**：只替换**等于本页陈旧自指号**的 token；带多个 ADR 号的 tags 多为**交叉引用**（如 `ADR-036` tags `[5,9]` 指其闭合的 ADR），**不得**按「自指」批量替换。

### 8.2 批量替换的三个「静默失效」陷阱（2026-10-08 实证，7 处数据丢失）

**事故**：`re.sub(pat, lambda m: new, txt)` —— **lambda 形式不会展开 `new` 里的 `\1` / `\2`**（只有字符串模板才展开）。于是 12 处替换里 7 处把「捕获组原文」替换成了**字面量 `\1`**，**原文丢失且脚本报绿**。

| # | 陷阱 | 症状 | 正解 |
|---|---|---|---|
| 1 | **`re.sub(pat, lambda m: new, t)`** | 捕获组内容消失，页面上出现裸 `\1` | `re.sub(pat, lambda m: m.expand(new), t)`；或直接用字符串模板（无反斜杠时） |
| 2 | **原始字符串 `r'...\n...'`** | `\n` 是字面反斜杠+n，**行尾被吃掉 → 两行黏成一行** | 需要真换行就别用 `r''`；行尾一律由「按行切片 + 依文件终止符 join」产生（原 rules/KR-014（已并入 lessons/WikiDriftCorrectionPitfalls）） |
| 3 | **A7 类表格列数判据** | 用 `line.count('|')` 数列数 ⇒ **别名链接 `[[A\|B]]` 的 `\|` 与行内 `\|...\|` 转义竖线都会虚增列数** ⇒ 把合规行误判成「5 列/6 列/7 列」 | 先 `re.sub(r'\[\[[^\]]*\]\]', 'LINK', line)` 屏蔽整个 wiki 链接，再 `replace('\\|','ESC')`，最后切列 |

**为什么会漏过**：三条都**不报错**。护栏只有两条 ——
```
① 写盘后全库扫「事故特征串」（字面  /  / 孤立的 
），命中即人工判别
② 表格类改动必须回读该表的列数分布（用上面第 3 行的正解）
```
⚠️ 扫描时**必须排除反引号内的教学用例**（本库 lessons / log 里有大量 `split("\n")` 之类的正文举例，实测 104 处），否则会把自己的教训当成损坏。

⚠️ 部分 `index.md` 的 ADR 表行**行尾没有 `|`**（如 ADR-036/060）—— `old_string` 以 `|` 结尾的 Edit 会失败，**先读该行真实字节**。

### 8.3 废止后不回收编号；旧号用「旧」前缀消歧

- **规则要点（原 rules/KR-019）**：重编号后新 ADR 可能与**已退役的旧号**同号不同页（两份都在盘上）；`merged_from` 字段按本库惯例**保留旧号**，⛔ 不"修正"它。
- **判据**：正文中裸写的旧号一律带 **「旧」前缀**（如「旧编号 ADR-021/048」）；`ADR-Index` 对应行须注明「⚠️ 指重排前旧编号，与现行 ADR-0NN 同号不同页」；页面自称号（`title:` / H1）必须与**文件名**一致（合并页可能残留模板号）。
- **盲区**：⚠️ 三个扫描器都看不见这类歧义 —— **可读标注是唯一缓解手段**。

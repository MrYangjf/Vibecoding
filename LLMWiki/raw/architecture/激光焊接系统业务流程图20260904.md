# 激光焊接系统业务流程图

> 本文档将激光焊接系统的业务流程图拆解为大模型可直接理解的结构化文本。
> **核心架构**：机器人服务器（主控）通过命令控制 5 个子设备运行（4 个实体设备 + 1 个虚拟算法设备）。系统存在**两套状态标识**：
> - **MainDeviceStatus（主设备运行态标识）**：系统级整体状态，对应流程图左侧泳道，共 6 种
> - **SubDeviceWeldStatus（子设备焊接状态标识）**：每个子设备各自维护的焊接流程状态，共 7 种
> **触发机制**：硬件按钮 / 机器人命令 / 软件UI 三种触发源统一映射到 IO，由 Running IO Work 扫描后驱动状态切换。

---

## 一、角色分层

### 1.1 机器人服务器（主控 / 命令发起方）

- **定位**：对外通讯入口，是整个系统的主控，**不是子设备**
- **职责**：
  - 对外通讯（Open / Connect On）
  - 维护 MainDeviceStatus（主设备运行态）
  - 接收机器人命令 / 软件UI指令，解析为虚拟IO触发
  - 向子设备下发控制命令，驱动子设备 SubDeviceWeldStatus 转换
  - 实时监控机器人坐标，写入寄存位
  - 接收子设备状态反馈，协调各子设备同步运行
- **IO 模式**：Running IO Work、Alarm IO Work、EMG IO Work（接收 EMG STOP / SAFE IO 信号）

### 1.2 子设备（执行方，共 5 个：4 个实体设备 + 1 个虚拟算法设备）

| 类型 | 子设备 | 核心职责 |
|------|--------|----------|
| 实体 | 控制器（Motion） | 轴控制、连续移动、送丝/对焦/振镜控制 |
| 实体 | 焊接头 | 焊接使能、焊接启动信号、送丝控制 |
| 实体 | 线激光 | 焊缝追踪、Y 偏移检测、轨迹规划 |
| 实体 | 监控相机 | 送丝距离检测、光斑对中、工作模式监控 |
| **虚拟** | **WeldParamControl（焊接参数控制）** | **算法对象，无物理实体。收集焊缝宽度、机器人坐标，输出焊接功率、送丝速度等工艺参数** |

> **注意**：
> 1. 每个子设备独立维护自身的 SubDeviceWeldStatus，状态转换由机器人服务器下发的命令触发。
> 2. WeldParamControl 是虚拟算法设备，不需要物理 Connect On 和轴/IO复位，在系统初始化时即加载，在焊接 Working 阶段运行算法。
> 3. WeldParamControl 的输入来自线激光（焊缝宽度）和机器人服务器（实时坐标），输出给焊接头/控制器（焊接功率、送丝速度等工艺参数）。

## 二、设备状态切换触发机制（IO 统一架构）

### 2.1 三种触发源

设备状态切换可由以下三种来源触发，最终统一到 IO 层：

| 触发源 | 说明 | 典型操作 |
|--------|------|----------|
| **硬件按钮** | 设备面板上的物理按钮，直接触发硬件 IO | 复位按钮、启动按钮、停止按钮、消除报警按钮、急停按钮 |
| **机器人命令** | 机器人服务器通过通讯接口下发的命令，解析为虚拟 IO 触发 | InitializeMachine、ResetMachine、StartMachine、StopMachine 等 |
| **软件 UI 按钮** | 上位机 / 触摸屏 / 调试界面上的虚拟按钮，通过软件接口解析为虚拟 IO 触发 | 软件界面上的复位、启动、停止、消除报警等按钮 |

### 2.2 统一触发流程

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  硬件按钮    │  │ 机器人命令   │  │  软件UI按钮  │
│ (复位/启动/  │  │(Initialize/ │  │(界面虚拟按钮)│
│  停止/消报/  │  │ Reset/Start │  │             │
│  急停)       │  │  /Stop...)  │  │             │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                  │
       ▼                ▼                  ▼
┌─────────────────────────────────────────────────┐
│              IO 层（统一触发点）                   │
│  硬件IO：硬件按钮直接电平触发                       │
│  虚拟IO：机器人命令/软件UI解析后置位               │
└──────────────────────┬──────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│         Running IO Work（持续扫描循环）            │
│  扫描所有IO状态，检测到触发IO后执行对应动作         │
└──────────────────────┬──────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│              执行动作 + 状态切换                    │
│  MainDeviceStatus 转换 + SubDeviceWeldStatus 转换 │
└─────────────────────────────────────────────────┘
```

### 2.3 关键设计要点

1. **统一入口**：无论触发源是硬件按钮、机器人命令还是软件UI，最终都表现为某个 IO 的触发，Running IO Work 只关心 IO 状态，不关心触发源。
2. **机器人命令解析**：机器人服务器收到命令后，不直接执行动作，而是将命令解析为对应虚拟 IO 置位，由 Running IO Work 统一扫描执行。这样保证硬件触发和软件触发走同一条执行路径。
3. **软件 UI 同理**：软件界面按钮点击后，通过通讯接口将指令发送到机器人服务器，机器人服务器解析为虚拟 IO 置位。
4. **Running IO Work 职责**：持续扫描 IO 状态，检测到触发后执行对应动作函数，并驱动 MainDeviceStatus 和 SubDeviceWeldStatus 转换。
5. **互斥与优先级**：急停 IO（EMG IO）优先级最高，可中断任何动作；报警 IO（Alarm IO）次之；普通运行 IO（Running IO）按正常流程处理。

### 2.4 硬件按钮与 IO 对应表

| 硬件按钮 | 对应 IO | 触发动作 | 状态转换 |
|----------|---------|----------|----------|
| 复位按钮 | Reset_IO | 执行设备复位 | M1→M2 / M5→M1 / M6→M1 |
| 启动按钮 | Start_IO | 启动设备运行 | M3→M4（含 Preworking→Working） |
| 停止按钮 | Stop_IO | 停止设备运行 | M4→M3（含 Stopping 流程） |
| 消除报警按钮 | ClearAlarm_IO | 清除报警状态 | M5→M1 |
| 急停按钮 | EMG_IO | 急停锁止 | 任意→M6 |

> 机器人命令和软件 UI 按钮通过解析后置位上述同名虚拟 IO，与硬件按钮共用同一执行路径。

## 三、两套状态体系定义与关系

### 3.1 状态体系总览

| 维度 | MainDeviceStatus（主设备运行态） | SubDeviceWeldStatus（子设备焊接状态） |
|------|----------------------------------|----------------------------------------|
| **维护者** | 机器人服务器（系统级） | 每个子设备各自维护（设备级） |
| **状态数** | 6 种 | 7 种 |
| **对应来源** | 流程图左侧泳道 | 用户明确定义 |
| **作用** | 标识整个系统的宏观运行阶段 | 标识单个子设备在焊接流程中的具体阶段 |

### 3.2 MainDeviceStatus（主设备运行态标识，6 种）

| 编号 | 状态名 | 颜色（对应PDF泳道） | 含义 |
|------|--------|---------------------|------|
| M1 | 设备未复位 | 灰色 | 程序刚载入，子设备尚未全部连接，不可执行焊接 |
| M2 | 设备复位中 | 黄色 | 正在执行各子设备的轴/IO复位动作 |
| M3 | 设备停止 | 蓝色 | 设备已就绪并待机，可接收启动命令；也是正常停止后的归宿 |
| M4 | 设备运行 | 绿色 | 设备正在执行焊接作业（含预检查和焊接中） |
| M5 | 设备报警 | 橙色 | 设备发生故障，需基于故障树和代码定位问题，等待人工处理 |
| M6 | 设备急停 | 红色 | 触发急停（EMG Stop），设备停机锁止，优先级最高 |

### 3.3 SubDeviceWeldStatus（子设备焊接状态标识，7 种）

| 编号 | 状态名 | 含义 |
|------|--------|------|
| S1 | `NoReset` | 未复位。子设备在自身复位流程完成前均处于此状态 |
| S2 | `Stanby` | 待机。子设备完成复位后进入此状态，等待机器人指令 |
| S3 | `PreWork` | 焊接前。接到机器人 Preworking 指令后，执行焊前检查 |
| S4 | `Working` | 工作中。接到机器人 Working 指令后，执行焊接作业 |
| S5 | `Stopping` | 停止中。焊接结束，接到机器人 Stopping 指令后进入停止流程 |
| S6 | `ErrorAborted` | 异常终止。机器人下发报警命令，子设备异常终止 |
| S7 | `ManualStopped` | 手动停止。机器人下发手动停止指令，子设备手动终止 |

### 3.4 两套状态的对应关系

主设备运行态是宏观阶段，子设备焊接状态是微观阶段，两者对应关系如下：

| MainDeviceStatus（主设备态） | 对应 SubDeviceWeldStatus（子设备态） | 说明 |
|-------------------------------|---------------------------------------|------|
| M1 设备未复位 | S1 `NoReset` | 子设备已连接但尚未复位 |
| M2 设备复位中 | S1 `NoReset`（复位执行中）→ 完成后 S2 `Stanby` | 复位过程中子设备仍为 NoReset，复位完成瞬间切到 Stanby |
| M3 设备停止 | S2 `Stanby` | 子设备待机，等待启动 |
| M4 设备运行 | S3 `PreWork` 或 S4 `Working` 或 S5 `Stopping` | 运行态涵盖焊前检查、焊接中、停止中三个子阶段 |
| M5 设备报警 | S6 `ErrorAborted` | 子设备异常终止 |
| M6 设备急停 | 任意状态 → 立即停机锁止 | 急停不改变子设备逻辑状态，直接物理锁止 |

> **关键理解**：M4（设备运行）是一个较宽的宏观状态，内部包含子设备的 PreWork → Working → Stopping 三个微观状态流转。M3（设备停止）对应子设备 Stanby。M5（设备报警）对应子设备 ErrorAborted。

## 四、MainDeviceStatus 状态机（主设备运行态）

### 4.1 状态转换图

```
┌──────┐  所有子设备   ┌──────┐  复位成功   ┌──────┐  Preworking  ┌──────┐
│  M1  │ ───────────→ │  M2  │ ──────────→ │  M3  │ ───────────→ │  M4  │
│未复位 │              │复位中 │             │ 停止 │              │ 运行 │
└──────┘              └──────┘             └──────┘              └──────┘
   │                     │                    ▲   ▲                  │  │  │
   │ Initialize Fail     │ ResetFail          │   │                  │  │  │
   ▼                     ▼                    │   │  焊接完成/手动   │  │  │
┌──────┐              ┌──────┐                │   │  终止            │  │  │
│      │              │      │                │   │                  │  │  │
│      │ ←────────────┘      │ ←──────────────┘   └──────────────────┘  │  │
│  M5  │   报警判断：故障树和代码                                          │  │
│ 报警 │ ←─────────────────────────────────────────────────────────────────┘  │
└──────┘   运行时报警 (Robot Alarm)                                            │
   ▲                                                                            │
   │                                                                            │
┌──────┐  EMG Stop（任意状态触发，优先级最高）                                │
│  M6  │ ←─────────────────────────────────────────────────────────────────────┘
│ 急停 │
└──────┘
   │
   │ 人工复位后
   ▼
  M1（重新开始）
```

### 4.2 状态转换规则

| 当前状态 | 触发条件/命令 | 目标状态 | 说明 |
|----------|---------------|----------|------|
| M1 未复位 | 所有子设备连接成功（Y） | M2 复位中 | 连接判断通过，自动进入复位 |
| M1 未复位 | 子设备连接失败（N, Initialize Fail） | M5 报警 | 连接失败直接报警 |
| M2 复位中 | 子设备复位成功（Y） | M3 停止 | 复位完成，进入待机 |
| M2 复位中 | 子设备复位失败（N, ResetFail） | M5 报警 | 复位失败直接报警 |
| M3 停止 | `StartMachine:Preworking` 命令 | M4 运行 | 接收启动命令，开始运行 |
| M4 运行 | 预检查失败（N, Pre-Working Fail） | M3 停止 | 预检查不通过，退回待机 |
| M4 运行 | 焊接正常完成（StopMachine:Complete） | M3 停止 | 焊接完成，正常停止 |
| M4 运行 | 手动终止 | M3 停止 | 人工手动停止焊接 |
| M4 运行 | 运行时报警（Robot Alarm） | M5 报警 | 焊接过程中发生故障 |
| 任意状态 | EMG Stop 急停信号 | M6 急停 | 优先级最高，立即停机锁止 |
| M5 报警 | 人工排除故障 + 消除报警 + 重新初始化 | M1 未复位 | 报警处理后重新走初始化流程 |
| M6 急停 | 人工复位 | M1 未复位 | 急停解除后重新走初始化流程 |

## 五、SubDeviceWeldStatus 状态机（子设备焊接状态）

### 5.1 状态转换图

```
                           ┌──────────────────────────────────────────┐
                           │                                          │
                           ▼                                          │
┌──────────┐  复位完成   ┌──────────┐  Preworking  ┌──────────┐   │
│ NoReset  │ ──────────→ │ Stanby   │ ───────────→ │ PreWork  │   │
│  (S1)    │             │  (S2)    │              │  (S3)    │   │
└──────────┘             └──────────┘              └────┬─────┘   │
     ▲                                                     │         │
     │                                                     │ Working │
     │                                                     ▼         │
     │                                              ┌──────────┐     │
     │                                              │ Working  │     │
     │                                              │  (S4)    │     │
     │                                              └────┬─────┘     │
     │                                                   │           │
     │                    ┌──────────────────────────────┼───────────┤
     │                    │                              │           │
     │           Stopping │                    手动停止  │  报警命令  │
     │                    ▼                              ▼           ▼
     │             ┌──────────┐              ┌──────────────┐ ┌──────────────┐
     │             │ Stopping │              │ManualStopped │ │ErrorAborted  │

     │                  │                             │                │

     │                  ▼                             ▼                ▼
     │             ┌──────────┐              ┌──────────┐      ┌──────────┐
     └─────────────│  复位流程  │ ←───────────│  复位流程  │ ←────│  复位流程  │
                   │ (回到S1)  │              │ (回到S1)  │      │ (回到S1)  │
                   └──────────┘              └──────────┘      └──────────┘
```

### 5.2 状态转换规则

| 当前状态 | 触发条件（机器人命令/事件） | 目标状态 | 说明 |
|----------|------------------------------|----------|------|
| —（上电） | 程序载入，子设备连接建立 | `NoReset` (S1) | 初始状态，复位完成前一直停留 |
| `NoReset` (S1) | 子设备自身复位流程完成 | `Stanby` (S2) | 复位完成，进入待机 |
| `Stanby` (S2) | 机器人下发 `Preworking` 指令 | `PreWork` (S3) | 开始执行焊前检查 |
| `PreWork` (S3) | 焊前检查通过，机器人下发 `Working` 指令 | `Working` (S4) | 开始执行焊接作业 |
| `PreWork` (S3) | 焊前检查失败 | `Stanby` (S2) | 检查不通过，退回待机，可重新发起 |
| `Working` (S4) | 焊接结束，机器人下发 `Stopping` 指令 | `Stopping` (S5) | 进入停止流程，执行焊接完成动作 |
| `Working` (S4) | 机器人下发手动停止指令 | `ManualStopped` (S7) | 手动终止焊接 |
| `Working` (S4) | 机器人下发报警命令 | `ErrorAborted` (S6) | 异常终止焊接 |
| `Stopping` (S5) | 停止流程完成 | `Stanby` (S2) | 正常停止，回到待机 |
| `ManualStopped` (S7) | 故障排除后重新复位 | `NoReset` (S1) | 走复位流程重新开始 |
| `ErrorAborted` (S6) | 故障排除后重新复位 | `NoReset` (S1) | 走复位流程重新开始 |

> **急停（EMG Stop）**：最高优先级信号，可在任意子设备状态触发，触发后所有子设备立即物理停机锁止，不改变逻辑状态，需人工复位后从 `NoReset` 重新开始。

## 六、主流程总览（同时标注两套状态）

```
【MainDeviceStatus: M1 设备未复位 | SubDeviceWeldStatus: S1 NoReset】
  开始
    ↓
  程序载入 (机器人服务器 InitializeMachine)
    ↓
  通讯建立 + 机器人服务器启动
    ↓
  4个实体子设备 Connect On + WeldParamControl虚拟设备初始化加载（各子设备进入 NoReset）
    ↓
  ◇ 所有子设备已连接？
    ├─ N → Initialize Fail →【M1 → M5 设备报警】
    └─ Y → 机器人下发 ResetMachine →【M1 → M2 设备复位中】

【MainDeviceStatus: M2 设备复位中 | SubDeviceWeldStatus: S1 NoReset】
  机器人下发 ResetMachine
    ↓
  控制器复位轴/IO ‖ 焊接头复位轴/IO ‖ 线激光/监控相机直接复位OK
    ↓
  ◇ 子设备复位成功？
    ├─ N → ResetFail →【M2 → M5 设备报警】
    └─ Y → 各子设备复位完成
            →【SubDeviceWeldStatus: S1 NoReset → S2 Stanby】
            →【MainDeviceStatus: M2 → M3 设备停止】

【MainDeviceStatus: M3 设备停止 | SubDeviceWeldStatus: S2 Stanby】
  设备待机
    ↓
  机器人下发 StartMachine:Preworking
    →【SubDeviceWeldStatus: S2 Stanby → S3 PreWork】
    →【MainDeviceStatus: M3 → M4 设备运行】

【MainDeviceStatus: M4 设备运行 | SubDeviceWeldStatus: S3 PreWork】
  设备运行检查（焊前检查）
    ├─ 运动控制器检查：Y轴/送丝Z/振镜轴/对焦Z 在位检测
    ├─ 控制流程检查：实时监控机器人坐标，写入寄存位
    ├─ 线激光设备检查：传感器启动&激光启动、追踪信号
    ├─ 焊接头使能：焊接启动信号发送机器人
    └─ 监控相机检查：送丝距离合规 → 出丝/光斑偏移 → 光斑对中
    ↓
  ◇ 子设备运行检测 OK？
    ├─ N → Pre-Working Fail
    │      →【SubDeviceWeldStatus: S3 PreWork → S2 Stanby】
    │      →【MainDeviceStatus: M4 → M3 设备停止】
    └─ Y → 机器人下发 StartMachine:Working
            →【SubDeviceWeldStatus: S3 PreWork → S4 Working】
            （MainDeviceStatus 保持 M4 设备运行）

【MainDeviceStatus: M4 设备运行 | SubDeviceWeldStatus: S4 Working】
  子设备焊接开始（5个子流程并行，含虚拟设备WeldParamControl）
    ┌─ 线激光子流程：Y偏移/焊缝宽度 → X坐标 → Y轴调整轨迹
    ├─ Motion子流程：轨迹 → 坐标 → 连续移动 → 送丝/对焦控制 → 振镜摆动
    ├─ WeldParamControl子流程：焊缝数据 → 坐标 → 工艺调整(摆幅/送丝/功率)
    └─ 监控相机子流程：工作模式判断 → 输出结果
    ↓
  ◇ 子设备运行时判断（机器人持续监控）
    ├─ 报警 → 机器人下发报警命令
    │         →【SubDeviceWeldStatus: S4 Working → S6 ErrorAborted】
    │         →【MainDeviceStatus: M4 → M5 设备报警】
    │         → 子设备异常终止 → 报警判断(故障树和代码)
    ├─ 手动停止 → 机器人下发手动停止指令
    │              →【SubDeviceWeldStatus: S4 Working → S7 ManualStopped】
    │              →【MainDeviceStatus: M4 → M3 设备停止】
    │              → 子设备手动终止
    └─ 焊接完成 → 机器人下发 StopMachine:Complete(Stopping指令)
                  →【SubDeviceWeldStatus: S4 Working → S5 Stopping】
                  （MainDeviceStatus 保持 M4 设备运行）

【MainDeviceStatus: M4 设备运行 | SubDeviceWeldStatus: S5 Stopping】
  焊接完成
    ↓
  子设备焊接完成动作
    ↓
  ◇ 子设备正常停止？
    └─ → 停止完成
         →【SubDeviceWeldStatus: S5 Stopping → S2 Stanby】
         →【MainDeviceStatus: M4 → M3 设备停止】

【终止后恢复】
  M5 设备报警 / S6 ErrorAborted → 人工排除故障 → 消除报警 → 重新复位 → M1 / S1 NoReset
  M3 设备停止 / S7 ManualStopped → 人工处理 → 重新复位 → M1 / S1 NoReset
  M6 设备急停 → 人工复位 → M1 / S1 NoReset
```

## 七、各阶段详细说明（同时标注两套状态）

### 阶段 1：程序载入与连接

**触发命令**：机器人服务器 `InitializeMachine`
- **MainDeviceStatus**：M1 设备未复位
- **SubDeviceWeldStatus**：子设备连接建立后进入 S1 `NoReset`

**动作内容**：

1. **机器人服务器（主控）**
   - 通讯 Open / Connect On
   - 启动机器人服务器
   - 建立 Running IO Work / Alarm IO Work / EMG IO Work

2. **实体子设备连接（机器人服务器下发，4 个实体子设备并行）**

   | 子设备 | 类型 | 连接动作 | 连接后 SubDeviceWeldStatus |
   |--------|------|----------|---------------------------|
   | 控制器 | 实体 | Connect On | `NoReset` (S1) |
   | 焊接头 | 实体 | Connect On | `NoReset` (S1) |
   | 线激光 | 实体 | Connect On | `NoReset` (S1) |
   | 监控相机 | 实体 | Connect On | `NoReset` (S1) |

3. **虚拟子设备初始化（WeldParamControl）**

   | 子设备 | 类型 | 初始化动作 | 初始化后 SubDeviceWeldStatus |
   |--------|------|------------|------------------------------|
   | WeldParamControl | 虚拟（算法） | 算法对象加载，参数初始化 | `NoReset` (S1) |

**判断节点**：所有子设备已连接？
- **是（Y）**：机器人下发 `ResetMachine` → MainDeviceStatus M1→M2
- **否（N）**：`Initialize Fail` → MainDeviceStatus M1→M5（设备报警）

### 阶段 2：子设备复位

**触发命令**：机器人服务器 `ResetMachine`
- **MainDeviceStatus**：M2 设备复位中
- **SubDeviceWeldStatus**：S1 `NoReset`（复位完成前持续此状态）

**复位动作（4 个实体子设备并行执行，虚拟设备无需复位）**：

| 子设备 | 类型 | 复位内容 |

| 监控相机 | 实体 | 直接复位 OK（无需轴复位） |
| WeldParamControl | 虚拟（算法） | 无需复位，初始化时已加载，直接进入 Stanby |

**判断节点**：子设备复位成功？
- **是（Y）**：
  - SubDeviceWeldStatus：S1 `NoReset` → S2 `Stanby`

- **否（N）**：`ResetFail` → MainDeviceStatus M2→M5（设备报警）

- **MainDeviceStatus**：M3 设备停止

### 阶段 6：焊接终止与状态切换

焊接过程中机器人服务器持续进行运行时判断，有三种终止路径：

#### 7.6.1 正常完成

**触发命令**：机器人服务器 `StopMachine: Complete`（即 Stopping 指令）

**状态转换序列**：
1. SubDeviceWeldStatus：S4 `Working` → S5 `Stopping`
2. MainDeviceStatus：保持 M4 设备运行
3. 停止流程完成后：
   - SubDeviceWeldStatus：S5 `Stopping` → S2 `Stanby`
   - MainDeviceStatus：M4 设备运行 → M3 设备停止

```
焊接完成（S4 Working / M4 运行）
  ↓ 机器人下发 Stopping 指令
状态切换：S4 Working → S5 Stopping（M4 保持运行）
  ↓
子设备焊接完成动作（S5 Stopping / M4 运行）
  ↓
◇ 子设备正常停止？
  └─ → 停止完成
       → 状态切换：S5 Stopping → S2 Stanby
       → 状态切换：M4 运行 → M3 停止
```

#### 7.6.2 异常终止

**触发命令**：机器人服务器下发报警命令

**状态转换**：
- SubDeviceWeldStatus：S4 `Working` → S6 `ErrorAborted`
- MainDeviceStatus：M4 设备运行 → M5 设备报警

```
子设备运行时判断 → 报警（S4 Working / M4 运行）
  ↓ 机器人下发报警命令
状态切换：S4 Working → S6 ErrorAborted
状态切换：M4 运行 → M5 报警
  ↓
子设备异常终止（S6 ErrorAborted / M5 报警）
  ↓
报警判断：故障树和代码
  ↓
（人工排除故障 → 消除报警 → 重新复位 → S1 NoReset / M1 未复位）
```

#### 7.6.3 手动停止

**触发命令**：机器人服务器下发手动停止指令

**状态转换**：
- SubDeviceWeldStatus：S4 `Working` → S7 `ManualStopped`
- MainDeviceStatus：M4 设备运行 → M3 设备停止

```
子设备运行时判断 → 手动停止（S4 Working / M4 运行）
  ↓ 机器人下发手动停止指令
状态切换：S4 Working → S7 ManualStopped
状态切换：M4 运行 → M3 停止
  ↓
子设备手动终止（S7 ManualStopped / M3 停止）
  ↓
（人工处理后 → 重新复位 → S1 NoReset / M1 未复位）
```

## 八、急停处理（EMG Stop）

急停信号可在**任意状态**触发，优先级最高，同时作用于两套状态：

```
EMG Stop 信号（来自 EMG IO Work，任意状态均可触发）
  ↓
MainDeviceStatus：任意状态 → M6 设备急停
SubDeviceWeldStatus：任意状态 → 立即物理停机锁止（不改变逻辑状态值）
  ↓
子设备停机锁止
  ↓
（人工复位后 → MainDeviceStatus 回到 M1 / SubDeviceWeldStatus 回到 S1 NoReset）
```

## 九、报警处理汇总

以下失败分支由机器人服务器判定并下发对应命令，同时驱动两套状态转换：

| 失败来源 | 错误标识 | 触发阶段 | MainDeviceStatus 转换 | SubDeviceWeldStatus 转换 |
|----------|----------|----------|----------------------|-------------------------|
| 子设备连接失败 | Initialize Fail | 程序载入 | M1 → M5 | 停留 S1 `NoReset` |
| 子设备复位失败 | ResetFail | 设备复位 | M2 → M5 | 停留 S1 `NoReset` |
| 焊前检查失败 | Pre-Working Fail | 焊前检查 | M4 → M3 | S3 `PreWork` → S2 `Stanby`（不报警，可重试） |
| 焊接运行时报警 | Robot Alarm | 焊接中 | M4 → M5 | S4 `Working` → S6 `ErrorAborted` |

> **注意**：`Pre-Working Fail` 不进入报警状态（M5），而是退回 M3 设备停止 / S2 `Stanby` 待机，可重新发起 Preworking。

## 十、机器人命令完整设计表

### 10.1 命令设计原则

1. **统一 IO 触发**：所有机器人命令到达机器人服务器后，均解析为对应虚拟 IO 置位，由 Running IO Work 统一扫描执行，与硬件按钮走同一路径。
2. **命令分层**：分为系统级命令（控制 MainDeviceStatus）和子设备级命令（控制 SubDeviceWeldStatus），子设备级命令通常由系统级命令内部自动下发，也支持单独调试时直接调用。
3. **前置条件校验**：每个命令执行前校验当前状态是否允许该转换，不满足则拒绝执行并返回错误码。
4. **查询命令独立**：查询类命令不触发状态转换，仅读取当前状态。

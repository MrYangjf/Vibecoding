## /workmap 工作地图更新工作流

### 唤醒方式

用户输入 `/workmap` 时触发。

### 核心原则

1. **不主动生成 Excel**：不会创建新的 WorkMap 文件
2. **读取已有文件**：找到项目目录中的 `AdaWeldSystem_WorkMap*.xlsx` 文件并读取理解
3. **增量更新**：在已有文件基础上更新信息，不破坏原有格式和内容

### 执行步骤

#### 步骤1：定位并读取 WorkMap 文件

1. 在项目目录中搜索 `AdaWeldSystem_WorkMap*.xlsx` 文件
2. 如果找到多个，选择最新的一个（按文件名中的日期或修改时间）
3. 如果没有找到任何 WorkMap 文件，**终止工作流并通知用户**："未找到 WorkMap 文件，请先手动创建"
4. 使用 `pandas` / `openpyxl` 读取 Excel 文件，理解其 Sheet 结构和列定义

#### 步骤2：读取 history.md

1. 读取 `history.md` 文件
2. 解析所有修改记录（四段式模板格式）
3. 提取每条记录的关键信息：
   - 序号、日期、任务编号
   - 涉及模块
   - 负责专员
   - 交付清单（文件路径 + 说明）
   - 审查结果

#### 步骤3：扫描项目最新状态

1. 扫描项目目录结构（排除 `bin/obj/.vs/.git/packages/Backup/Skills/`）
2. 统计各模块 `.cs` 文件数量和代码行数
3. 对比 Excel 中记录的文件结构，识别新增/删除的文件

#### 步骤4：更新 Sheet1 - 项目文件夹结构图

**更新内容**：
1. **更新文件夹结构**：将 Excel 中的文件夹树形结构替换为最新实际结构
2. **描述模块名称**：在每个模块文件夹行旁边标注模块中文名称
3. **显示编写进度**：在每个模块文件夹行旁边标注当前编写进度（百分比或状态文字）

**模板格式参考**（基于原始模板 `AdaWeldSystem_WorkMap_20260617.xlsx`）：
```
列 A: 文件夹树形结构（ASCII art）
列 B: 模块内容描述（仅模块文件夹行填写，如"SmartRay相机模块"）
列 C: （空）
列 D: 编写进度（仅模块文件夹行填写，如"100%"或"进行中"）
```

**更新规则**：
- 保留 Sheet1 的项目基本信息区域（Row 0~16）不变
- 替换文件夹结构区域（Row 19+）为最新结构
- 在每个模块文件夹行（如 `├── SmartRayCam/`）的 B 列填写模块名称
- 在每个模块文件夹行的 D 列填写编写进度

#### 步骤5：更新 Sheet2 - 模块任务清单

**更新内容**：
1. **新增模块任务**：如果项目中有新模块（Excel 中不存在），按原格式在末尾追加该模块的任务行
2. **更新已有模块任务**：对每个已有模块的任务行，更新以下字段：
   - **最后修改日期**（实际完成日期列）：根据 history.md 中该模块的最新记录更新
   - **状态**：根据 history.md 中的审查结果更新（已完成/进行中/未开始）
   - **交付物/备注**：根据 history.md 中的交付清单更新
   - **修改记录索引**：根据 history.md 解析后写入（如 `#15`、`#22,#23`）

**模板格式参考**（基于原始模板 Sheet2 列定义）：
```
列 A: 功能模块（仅模块首个任务行填写，其余为空）
列 B: 任务阶段（技术路线/业务逻辑/结构搭建/代码实现/UI界面与触发事件/代码审查与优化/BUG持续改进）
列 C: 任务描述
列 D: 涉及模块/文件
列 E: 开始日期
列 F: 预计完成日期
列 G: 实际完成日期
列 H: 状态（已完成/进行中/未开始）
列 I: 优先级（高/中/低）
列 J: 交付物/备注
列 K: 修改记录索引（如 #1、#2,#3）
```

**新增模块任务模板**（按原格式追加）：
```
任务阶段顺序：技术路线 → 业务逻辑 → 结构搭建 → 代码实现 → UI界面与触发事件 → 代码审查与优化 → BUG持续改进
每个阶段一行，列 A 仅第一行填写模块名称，其余为空
```

**修改记录索引规则**：
- 修改记录索引对应 `history.md` 中的记录序号
- 格式：`#{序号}`，多条记录用逗号分隔（如 `#22,#23,#24`）
- 索引内容是读取 `history.md` 后，根据该任务涉及的文件路径和模块匹配到的记录序号

#### 步骤6：保存并通知用户

1. 将更新后的 Excel 保存回原文件（覆盖保存）
2. 通知用户更新结果：
   - 更新了哪些 Sheet
   - 新增了哪些模块任务
   - 更新了哪些已有任务的状态
   - 文件路径

## history.md 解析规则

### 解析目标

从 `history.md` 中提取每条修改记录的关键信息，用于更新 Sheet2 的任务状态和修改记录索引。

### 解析字段映射

| history.md 字段 | Sheet2 对应列 | 说明 |
|----------------|--------------|------|
| 序号（如 `[26]`） | 修改记录索引（列 K） | 格式为 `#26` |
| 日期（如 `2026-06-24`） | 实际完成日期（列 G） | 仅当状态为"已完成"时更新 |
| 涉及模块 | 匹配功能模块（列 A） | 用于定位需要更新的任务行 |
| 负责专员 | — | 参考信息 |
| 交付清单 | 交付物/备注（列 J） | 追加到现有备注后 |
| 审查结果 | 状态（列 H） | 全部通过→已完成，部分通过→进行中 |

### 匹配逻辑

1. 读取 history.md 中每条记录的"涉及模块"字段
2. 提取模块路径前缀（如 `EmguALG/`、`UIDesign/Sub2UI/`）
3. 匹配到 Sheet2 中对应模块的任务行
4. 更新该模块所有任务行的状态和修改记录索引

## 模块编写进度计算规则

| 状态 | 进度值 | 判定条件 |
|------|--------|---------|
| 100% | 已完成 | 所有任务阶段均为"已完成" |
| 80% | 收尾中 | 代码实现已完成，仅剩代码审查和BUG修复 |
| 60% | 开发中 | 代码实现阶段有"进行中"任务 |
| 40% | 开发中 | 结构搭建/业务逻辑阶段有"进行中"任务 |
| 20% | 规划中 | 仅技术路线阶段已完成 |
| 0% | 待开发 | 所有任务均为"未开始"或模块文件夹不存在 |

## 技术实现要点

### 文件扫描
- 使用 Python `os.listdir()` 和 `os.walk()` 扫描项目目录
- 排除 `bin/`, `obj/`, `.vs/`, `.git/`, `packages/`, `Backup/`, `Skills/`
- 统计 `.cs` 文件数量（排除 `.Designer.cs`）
- 统计代码行数（排除空行和纯注释行）

### Excel 操作
- 使用 `openpyxl` 库读取和写入 Excel
- **保留原有格式和样式**：不修改字体、颜色、边框、列宽等格式
- 仅修改单元格的值（文本内容）
- 新增行时复制相邻行的格式

### history.md 解析
- 使用正则表达式匹配 `### [序号] 修改记录 - YYYY-MM-DD TASK-XXX` 格式
- 提取四段式内容：需求总结、任务清单、交付清单、审查结果
- 解析审查结果中的 `[x]` 和 `[ ]` 判断完成状态
